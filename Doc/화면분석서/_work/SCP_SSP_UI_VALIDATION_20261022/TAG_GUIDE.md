# 적용 TAG 분류 기준서 (2026-10-23 사용자 지시)

배경: 취합 엑셀의 TO-BE 적용여부 "부분적용" 은 사용자에게 "TO-BE 가 일을 덜 했다"로 읽힌다. 차단 시트에 실린 행은 TO-BE 에서도 검사·차단은 있다는 뜻이므로 값을 **"적용"** 으로 바꾸고, AS-IS 와 다른 점은 옆 칸 **적용 TAG** 로 설명한다.

## TAG (사용자 지정 4종 — 이 4개만 사용, 여러 개 가능)
| TAG | 언제 |
|---|---|
| `[AS-IS 결함 교정]` | AS-IS 동작이 결함(롤백 누락, 잘못된 조건·변수, 오타 컬럼, 실패인데 성공 반환, 무한루프 등)이고 TO-BE 가 이를 바로잡아 동작이 달라짐 |
| `[반환값 상실·영향 없음]` | 반환 코드·OUT 값·결과셋·로그/이력 기록·메시지 문자열 등 **부가 산출물**이 빠지거나 달라졌으나, 호출자(부모 SP·화면)가 그 값을 쓰지 않아 사용자 결과(차단 여부·저장 결과)는 같음 |
| `[예외 전파 변경]` | 오류 처리 경로가 바뀜 — 예외를 삼키던 것이 전파되거나 반대, 롤백 범위·시점 변경, RAISERROR→RAISE_APPLICATION_ERROR 로 메시지·코드 경로 변경, 후속 처리(메일 등) 실패가 본 처리 실패로 이어지는 등 |
| `[판정 결과 차이]` | 같은 입력에 대해 막느냐/통과하느냐, 검사 대상·범위(행·항목·Division·기간), 조건식, 경계값, 검사 시점·순서, 화면이 결과를 쓰는 방식이 달라 **사용자가 겪는 결과가 달라질 수 있음** |

- 판단 순서: 사용자 결과가 달라지면 `[판정 결과 차이]` 는 반드시 포함. 그 원인이 AS-IS 결함 교정이면 둘 다. 사용자 결과가 같고 부가 산출물만 다르면 `[반환값 상실·영향 없음]`.
- 메시지 문구·번호만 다른 차이는 TAG 대상이 아님(메시지 의미 대조로 별도 처리). 그 차이 **밖에** 다른 차이가 없으면 `tags` 는 [] 이고 `reason` 에 "메시지 차이만"이라 쓴다.
- 4종 어디에도 맞지 않으면 `tags`=[] + `reason` 에 "분류 외: …" 로 무엇이 다른지 적는다(임의 TAG 신설 금지).
- 추측 금지: 입력의 tobe_basis / tobe_cmp.diff / fe_downgrade_reason 문구로 판단하고, 문구가 애매하면 그 안의 파일·라인(AS-IS `C:\Projects\NSCM\Doc\asisfacts\db\modules\`, AS-IS C# `C:\Projects\NSCM\..\GSCM` 는 asis_loc 경로, TO-BE PKG 사본 `C:\Projects\NSCM\Doc\화면분석서\_work\SCP_SSP_UI_VALIDATION_20261022\` 아래 tobe 원문 폴더 또는 `nscm-fe/`)을 Read 해 확정. 그래도 못 정하면 `tags`=[] + `reason`="미확인: …".

## 출력
`tag_out/tNN.jsonl` — 입력 행마다 1줄, 입력 순서 유지:
```
{"key":"DB:SSP0003#12","tags":["[AS-IS 결함 교정]","[판정 결과 차이]"],"reason":"AS-IS 는 실패 후 ROLLBACK 누락으로 일부 반영, TO-BE 는 전체 롤백 — 같은 입력에서 저장 결과가 다름"}
```
- reason: 한국어 1~2문장, 사용자에게 무엇이 다른지(코드 용어 최소화).
- 파일 수정 금지(출력 1개만). 최종 응답: TAG별 건수, tags=[] 행 목록(키·사유), 애매했던 점 3개 이내.
