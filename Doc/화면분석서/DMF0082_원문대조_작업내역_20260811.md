### 주석 1 — No.65 원문의 "81 Div는 End Customer 컬럼 미사용"

원문은 81 이 End Customer 를 안 쓴다고 적었으나, **AS-IS 메타는 반대**입니다.

- AS-IS `DMF0003` `Mkt Fcst` 시트 `END_CUSTOMER` = `82,81,81_UC,…` **노출(VISIBLE='Y')**
- 같은 문서 **No.64(Div=81)** 가 "신규 행 Insert 후 End Customer 정상 Mapping" 을 요구 — 81 이 End Customer 를 쓴다는 전제

⇒ 두 항목이 서로 충돌하며, **AS-IS 메타 + No.64 를 근거로 81 의 End Customer 유지**를 채택했습니다.
"As-Is 29개 / 현재 21개" 의 21개는 문서 작성 시점(08-06) 값이고, 현재는 33개로 그 시점 격차는 해소됐습니다.

### ① No.63-① ② — AS From Site 활성/비활성 + 콤보  ✅ 해소

**적출 당시 상태**: `SCM_MST_SHEET_COLUMNS.AS_FROM_SITE.INPUT_TP_CD = 'S'` → `cellEditableHandler` 의 메타
게이트(IM/IO/M/O 한정)에서 **항상 차단**. FE 의 `AS_FROM_SITE` 콤보는 Incoterms 스왑 판정용으로만 쓰이고
컬럼에 바인딩돼 있지 않았다. 08-05 에 신설한 저장 파라미터 `p_as_from_site` 가 입력값을 받을 경로도 없었다.
**원인** = No.35(Div 40, 입력 8컬럼) 메타 게이트 도입 시 No.63(Div 81)의 9번째 편집 컬럼을 함께 반영하지 않음.

**AS-IS 원문 계약** (`DMF0003_MktFcst.cs` [E20260211-001189] — 셀변경 L3444~3510 / FCST Type 변경 L3556~3600):
세 축이 **모두** 성립할 때만 활성이다. 원문 문서보다 조건이 하나 많다.

| 축 | 조건 | AS-IS 근거 |
|---|---|---|
| ① division | `81*` 또는 `82` | `.cs L3445 Substring(0,2)=="81" \|\| =="82"` |
| ② Sales Site | AS(비축)향이 **아님** | `dtAsSalesSite.Select("Name = '<SCM_SITE_ID>'")` 미매칭 |
| ③ FCST Type | **W/S 계열** | `GetLookupValues("FCST_TYPE","DM Planner (W/S)")` → `UP_FX_GetCommonDataList_DM` L72~79 = `SALES_TYPE_CODE2` |

3. 편집 진입 시 컬럼 dataMap 을 `AS_FROM_SITE`(param1=division) 후보로 스왑 (AS-IS `.cs L2615~2616` `SetCellTypeCombo`).

### ② No.40-② — Measure Setting 팝업 컬럼 사이즈 조절  ✅ 해소

`ColumnSelectDualList` 는 Wijmo 가 아니라 **순수 `<table>`** 이라 리사이즈 기능이 아예 없었다.
헤더 우측 경계에 grip 을 두고 pointer 이벤트로 폭을 조절하도록 신설했다
(`table-layout: fixed` 이므로 `<col>` 폭만 갱신하면 즉시 반영. 좌/우 grid 독립, 최소 폭 48px).

**공용 컴포넌트 영향 범위**: opt-in prop **`resizableColumns`**(기본 `false`)로 넣어
기존 사용처(`ColumnSettingModal` — DMF0020 / DMF0043_01)는 **무영향**이고, `MeasureSelectModal` 만 활성화했다.
다른 화면에도 필요하면 prop 한 줄만 추가하면 된다.
