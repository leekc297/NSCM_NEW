## 1. 공통 구조 — 편집 가능 여부는 4개 층이 겹쳐서 정해진다

| 층 | 무엇을 보나 | 원천 | 어디서 판정 |
|---|---|---|---|
| ① 버튼 권한 | 그룹 × 메뉴 × 버튼 | `SCM_ADM_USER_GR_MNU_BTN_MPG_M` + `SCM_ADM_MNU_BTN_MPG_M` | `PKG_NSCM_UI_COM_AUTH.PR_GET_MNU_BTN_AUTH_DIV` → FE `useTabBtnPermissions().hasButton()` |
| ② 컬럼 편집 | 컬럼별 입력 유형 | `SCM_MST_SHEET_COLUMNS.INPUT_TP_CD` (M/O = 편집, IM/IO = 신규행만, S = 잠금) | 공용 `GridUtils.isEditableCell` |
| ③ 행 편집 | 행별 `EDIT_FLAG` (`'N'` 이면 행 잠금) | 조회 SP 결과셋 | 공용 `GridUtils.isEditableCell` (`EDIT_FLAG !== 'N'`) |
| ④ 화면 전용 규칙 | 메저 권한·사업부 허용·시점·버킷 등 | 화면별 SP 커서·룩업 | 각 화면 `beginningEdit` / `editLock.ts` |

### 1-1. 버튼 권한(①)의 동작 — 주의할 점 2가지
1. **시트를 구분하지 않고 메뉴 단위로 합친다.** `hasButton = buttons.includes(btnCd)` 라서 `titleSet` 시트(컬럼 설정 저장)에만 준 `SAVE` 도 메인 그리드의 `hasButton('SAVE')` 를 `true` 로 만든다.
2. **사업부 `EDIT_YN` 은 보지 않는다.** 단일 Division 선택 시 "그 Division 단위권한 행이 있는 그룹"만 인정하는데, `EDIT_YN='N'` 행도 단위권한 행이므로 통과한다(`PR_GET_MNU_BTN_AUTH_DIV` L144~152).

### 1-2. 행 `EDIT_FLAG`(③)를 만드는 SP 의 공통 식
대부분 `CASE WHEN 행의 팀 = 사용자 팀(FN_GET_DEPT_LIST 등) OR V_GROUP_ID = 'ADMIN' THEN 'Y' ELSE 'N'`.

`V_GROUP_ID = 'ADMIN'` 은 룩업 `GET_ADMIN_GROUP`(`SEGMENT2='ALL'`)에 사용자의 그룹이 있으면 성립한다. 현재 등록된 그룹:

| SEGMENT1 | SEGMENT2 |
|---|---|
| ADMIN · DM ADMIN · **DM Planner** · SCM PI Admin · **SCP Planner** | ALL |
| DM Planner | DMF000 |
| DM Planner (W/S) | DMF0003 |
| SCP Planner | DMF0039 |
| ADMIN · SCM PI Admin | SCP0120 |

→ 이름은 'ADMIN' 이지만 실제로는 **DM Planner·SCP Planner 도 전 행 편집** 대상이다. **DM Viewer 는 없다.**

### 1-3. 사업부 편집권 `EDIT_YN`
- 원천: `SCM_ADM_USER_GR_UNIT_AUTH_MPG_M.EDIT_YN` (사용자 × 그룹 × Division)
- 조회 경로: `PKG_SCM_USER_MNU.PR_SCM_EDIT_YN(user, menu)` = 뷰 `SCM_ADM_USER_MNU_EDIT_AUTH_V`(그룹들 중 `MAX(EDIT_YN)`)
- 실측(USE_YN='Y'):

| 그룹 | EDIT_YN='N' 사용자 | EDIT_YN='Y' 사용자 |
|---|---|---|
| DM Viewer | 419 | **3** (40·81계열·82) |
| SCM Viewer | 1,520 | **1** |
| FP Viewer / SSP Viewer / GMES Viewer | 1,764 / 322 / 3 | 0 |
| 그 외 Planner·Admin 그룹 | 0 | 전원 |

- 이 값을 **SP 가 내려줘도 FE 가 쓰는 화면은 일부뿐**이다(§2 표의 "EDIT_YN 사용" 열).
