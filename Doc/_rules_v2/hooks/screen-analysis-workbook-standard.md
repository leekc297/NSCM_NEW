## §1. 원칙 (4대)

개발자가 **보고 바로 개발할 수 있고**, 현업/QA 가 **읽고 바로 이해할 수 있는** 문서.
1. **전수·실측** — 나열식 요약 전재 금지. AS-IS 평문 정본 + 사내 DB 실측만. 추측 0 (anti-simplification).
2. **UI + DB 동시 분석** — 화면 UI 뿐 아니라 AS-IS 소스가 쓰는 DB 계층(SP·PKG·Function·Lookup·Combo·권한·Division·일자/편집 제약)을 함께 전수 분석(§1.5). 분석은 전수로 하되, **문서에는 그 결과를 자연어로 풀어 쓴다**.
3. **가독성 = 전면 자연어** — 각 항목을 **사람이 대화하듯** 설명. 원시 코드 표현(예: `clbDivisions.ControlValues.Substring(0,2)=="81"`, SQL 문장, `.cs` 라인번호)을 그대로 옮기지 않는다. **식별자(SP/PKG/FUNCTION/COLUMN/SHEET/MSG ID/테이블명)만 원문**으로 남긴다. 별도 "쉬운 설명" 열·"줄" 열은 만들지 않는다.
4. **정직한 격차·공백 표기** — "검증 없음/분기 없음/미구현/비활성"은 핵심 가치. 없는 것을 지어내지 않고, 자료 간 수치가 다르면 **양쪽을 병기**하고 확인 필요로 남긴다.

원천 3원: ① AS-IS 평문 정본 전수(추측 금지) ② 사내 메타/SP **실데이터**(ora.py SELECT) ③ TO-BE 현재 구현 + 실측 효과.
⚠️ **Figma = 디자인 참조 only** — LAYOUT 이미지/배치 참조일 뿐 정책 확정 룰 아님(권한/편집/필수값/Validation/콤보 값 등 정책 판단 금지). 상세 = `figma-layout-parity-mandatory` §1.5.

## §1-D. EVENT 시트 = 목차 + **선행 MD 전문 승계** (2026-07-29 사용자 지시 — 설계서 의무)

> 사용자 지시(2026-07-29): "event sheet 의 하단 상세 내역에 md 내역 가져와서 채워주세요."

EVENT 시트를 목차만으로 끝내면 **설계서 단독으로 개발이 불가**하다. 2단 구성이 의무:

| 구간 | 내용 |
|---|---|
| 상단 — 목차 | `E01…En` × (언제 / 무엇이 어떻게). MD 의 `##`(이벤트) 는 E 번호, `###`(단계) 는 들여쓴 하위 행. |
| 하단 — **상세** | 선행 산출물 `{ID}_{화면명}_주요이벤트_상세분석.md` **본문 전 행**을 (구분 / 항목 / 내용) 3열로 승계. 계층 표기 = `■ 이벤트` / `· 단계` / `내용` / `표` / `코드·식별자`. |

의무 규칙:
1. **무축약 승계** — MD 본문 행을 요약·선별하지 않는다(anti-simplification). 행 수는 "MD 유효 행 ≤ EVENT 시트 행" 이어야 하며 대사 보고에 포함한다.
2. **표기만 정리** — §2 자연어 원칙에 맞춰 **라인번호(`L123`, `(L123~L456)`, `— L12, L34`)·백틱·굵게(`**`) 표기만 제거**하고 문장·식별자는 그대로 둔다. 산출 후 `\bL\d{2,}` grep **0건** 확인 의무(승계한 UI분석서 텍스트에도 동일 적용).
3. **MD 표는 셀 분해** — `| a | b |` 를 문자열로 넣지 말고 파이프로 분해해 열에 배치, 구분선(`|---|`) 행은 제거.
4. 코드블록(```)은 펜스만 제거하고 내용은 `코드·식별자` 구분으로 보존.
