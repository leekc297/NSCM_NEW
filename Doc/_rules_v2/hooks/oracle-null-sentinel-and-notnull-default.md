# Hook — Oracle 널 센티널 `'/'` 과 NOT NULL 초기값 (MSSQL `ISNULL(x,'')` 이관 규약)

> 신설: 2026-07-30 (사용자 확정 `'-'` — DMF0044/0049 PKG 변환결함 전수 감사 후)
> ⭐ **개정: 2026-10-15 사용자 지시(GAP 358/467/257) · 2026-10-19 본문 반영** — 신규 NULL 초기값·비교 센티널 = `'/'`, 원래 데이터가 `'-'` 인 값은 유지, 과도기 빈값 술어 `IN ('-','/')`. §0.5 가 정본이며 §1~§3 은 `'/'` 기준으로 고쳐 두었다.

## §0. 왜 이 룰이 있는가

MSSQL 은 **빈 문자열이 실제 값**이라 `ISNULL(x, '')` 을 두 목적으로 쓴다.

1. **JOIN 키·값 비교 정규화** — NULL 을 `''` 로 바꿔 양쪽을 비교 가능하게 만든다
2. **NOT NULL 컬럼 채우기** — NULL 대신 `''` 를 넣어 제약을 통과한다

Oracle 은 **빈 문자열이 곧 NULL** 이라 두 목적이 **모두 깨진다**. 게다가 오류가 나지 않고
**조용히 틀린 값**을 보여주는 경우가 많아, 화면을 열어보기 전까지 드러나지 않는다.

실증(사내 실측 2026-07-30): DMF0044 에서 이 계열 **477건** 정정. 그중 `GET_SALES_REPORTS_DATA` 는
`TO_CHAR(SYSDATE,...)` 를 DATE 컬럼에 넣어 **ORA-01861 로 조회가 통째로 실패**하던 상태였다.

## §0.5 ⭐ 개정 2026-10-15 — 센티널 `'-'` → `'/'` (사용자 상시 지시, 별도 개정 대상 아님 — 작업과 동시에 적용)

> 사용자 원문(2026-10-15 GAP 358): "오라클에서 NVL(x,'-') 는 NVL(x,'/') 로" / (GAP 467): "원래 데이터가 '-' 로 들어 있던 부분이면 유지하고, 초기값으로 NULL 을 처리하는 것은 '/'" /
> (GAP 257): "과도기에는 '-', '/' 가 같이 존재할 수 있으므로 둘 다 허용" / (2026-10-19 SCP0096): "PKG 이식 시 '/' 기준으로 작성. 별도 개정 대상으로 분류하지 않고 작업 시 같이 작업".

| 상황 | 규칙 |
|---|---|
| 신규 NULL 초기값 (NOT NULL INSERT · GTT 스테이징 · payload) | **`NVL(x,'/')`** (숫자 `NVL(x,0)` · DATE `SYSDATE` 는 종전 동일). DDL `DEFAULT ON NULL '/'`(10-08 SLASHDEF) 와 같은 방향 |
| 비교·JOIN 정규화 (신규 작성) | 양변 **`NVL(x,'/')`**. 센티널이 실제 쓰이는 컬럼은 과도기 양변 `DECODE(x,'-','/',NVL(x,'/'))`. 실값 키(ITEM_ID·PROJECT_CODE 등)는 raw 유지 — PK 인덱스 |
| 빈값 술어 | **`IN ('-','/')`** — 이관 원장의 `'-'` 와 신규 `'/'` 가 공존(기존 데이터 일괄 변환 없음) |
| 원래 데이터가 `'-'` 인 값 | **유지** — `'/'` 는 NULL 을 채우는 초기값 전용. 값이 `'-'` 인지 판정은 TO-BE 이관 사본 등 원천으로(AS-IS DEV `''` ↔ 사본 `'-'` 갈림 사례 GAP 467) |
| AS-IS 가 `'-'` 를 **실값**으로 쓰는 컬럼 | `x = '-'` 비교 유지(9월 이전 AS-IS 실측으로 판정) |
| 금지 | `NVL(x,'-')` · `DEFAULT '-'` 신규 작성(하네스 check-pkg **P39 BLOCK**) · `'-'` 단독 비교는 **P40 WARN**(사유 기록) · `NVL(x,NULL)`(#127) |
| MERGE 원천 | 조인 키와 같은 정규화로 GROUP BY (ORA-30926 방지) · 치환은 문장 단위([[feedback_sentinel_replace_statement_unit_groupby]]) |

적용 선례: `PKG_DMF0042 [E20261015-GAP257]` · `PKG_DMF0042 INCOTERMS NVL '/'`(GAP261) · 10-06~08 SLASHOBJ/SLASHDEF. 메모리: `feedback_oracle_nvl_sentinel_slash` · `feedback_slash_transition_accept_both`.

## §1. 센티널은 `'/'` 로 통일 (2026-07-30 `'-'` 확정 → 2026-10-15 `'/'` 개정)

빈 문자열을 대신할 값은 **`'/'`** 로 통일한다. `''`(=NULL) / `'-'`(신규 작성) / `'X'` / 공백 등 임의 값 금지.

이관 원장에 남은 `'-'` 와 AS-IS 가 실값으로 쓰던 `'-'` 는 변환하지 않으므로(§0.5),
**NULL ≡ `'/'` ≡ 이관 빈값 `'-'`** 를 같은 뜻으로 취급한다 — 빈값 술어 `IN ('-','/')`.

### §1.5 ⭐ 센티널 변형 3형(`' '`/`'-'`/`'--'`) = `'/'` 통일 + 초기값 `NVL(x,'/')` (2026-08-07 `'-'` 확정 → 2026-10-15 `'/'` 개정)

> 사용자 지시 원문: "AS-IS 의 ' ', '-', '--' 은 '-' 로 처리합니다." / "초기값 처리로 NVL(x,'-') 해서 필요한 초기값 처리하는 것도 RULE 로 추가해주세요."

1. **변형 3형 통일**: AS-IS 이관 데이터에는 "값 없음"이 `' '`(공백)·`'-'`·`'--'` 3형으로 혼재한다
   (실사고: DMF0082 `DM_PLN_CFM_SELLING_PRICE.PLANT_SITE_ID` 동일 키에 3형 공존 —
   판가 52주 검증의 10키 정확 조인이 **변형별로 갈라져** 판가가 있는데도 "Unit Price Not Found" 차단, 2026-08-07 실측).
   **정본 = `'/'` 단일(10-15 개정 — 원장에 이미 있는 `'-'` 는 유지, §0.5).** 처리 지점:
   - **비교·JOIN·검증 술어**: 양변 변형 정규화 — `CASE WHEN x IS NULL OR TRIM(x) IS NULL OR x IN ('-','--','/') THEN '/' ELSE x END`
     를 **양변**에 적용(센티널이 실제 쓰이는 컬럼만 — 실값 키는 raw 유지).
   - **신규 적재·GTT 스테이징 1지점**: 적재 시 `'/'` 로 정규화 (PK 센티널 표준 — GTT 1지점 원칙).
   - ⚠️ **원장(raw) 일괄 UPDATE 정규화는 즉시 실행 금지** — 동일 키의 변형 행이 공존하므로 PK/UNIQUE 충돌·합산 검증 선행 의무
     (PKSENTINEL 표준 절차: 충돌 검증 → 합산/병합 → 배치. `DBWORK_7UI_PKSENTINEL_TRUNC` 계보).
     그때까지 DML(MERGE ON) 키는 행별 원본 변형을 보존한다(무단 정규화 = MERGE 미매칭 → 변형 중복 행 신설 사고).
2. **초기값 = `NVL(x,'/')`**: 신규 행 적재·화면 payload·GTT 스테이징에서 값이 없는 문자 키/속성 컬럼의 초기값은
   **`NVL(x,'/')`** 로 처리한다 (숫자 `NVL(x,0)` / DATE `SYSDATE` 는 §3 동일). `''`·`' '`·`'-'`·`'--'` 임의 초기값 금지.

| 현행(오역) | 정정 |
|---|---|
| `NVL(x,'') <> ''` | `x IS NOT NULL` |
| `NVL(x,'') = ''` | `x IS NULL` |
| `NVL(x,'') <> 'LIT'` | `(x IS NULL OR x <> 'LIT')` |
| `NVL(a,'') = b` / `NVL(a,NULL) = NVL(b,NULL)` | **`NVL(a,'/') = NVL(b,'/')`** (센티널 컬럼 과도기: `DECODE(a,'-','/',NVL(a,'/')) = DECODE(b,'-','/',NVL(b,'/'))`) |
| `x = '-'` (센티널 리터럴 비교) | **`NVL(x,'/') IN ('-','/')`** (AS-IS 가 `'-'` 를 실값으로 쓰는 컬럼은 `x = '-'` 유지) |
| 공백까지 정규화 필요 시 | `NVL(NULLIF(TRIM(a),''),'/') = NVL(NULLIF(TRIM(b),''),'/')` |

⛔ **한쪽만 보정 금지** — 반대편이 NULL 이면 여전히 매칭되지 않는다.
AS-IS 가 한쪽만 `ISNULL` 이었어도 Oracle 에서는 양변에 적용한다.

### 판정 기준 = 술어냐 표시냐

| 위치 | 영향 | 조치 |
|---|---|---|
| **술어** (`WHERE` / `JOIN ON` / `CASE WHEN`) | 항상 거짓 → 행 전멸 / `CASE` 가 언제나 `ELSE` | **정정** |
| **표시** (`SELECT` 리스트, `THEN`/`ELSE` 값) | Oracle 은 연결 시 NULL 을 빈문자로 취급 → 결과 동일 | **유지** |
| **대입** (`V_X := ''`) | 영향 없음 | 유지 |

## §3. NOT NULL 컬럼 초기값 의무

INSERT 대상 컬럼이 `NULLABLE='N'` 이면 값 식을 반드시 감싼다.

| 컬럼 타입 | 초기값 |
|---|---|
| 문자 (`VARCHAR2` / `CHAR`) | `NVL(x, '/')` (10-15 개정 · DDL `DEFAULT ON NULL '/'` 동일 방향 — ⛔ `NVL(x,'-')` 신규 작성 금지) |
| 숫자 (`NUMBER`) | `NVL(x, 0)` |
| 날짜 (`DATE`) | `SYSDATE` 등 명시값 — ⛔ `TO_CHAR(SYSDATE,'...')` **금지**(문자열이라 ORA-01861) |

### 작성 절차 (의무)

```sql
-- 1) 대상 테이블의 NOT NULL 컬럼 인벤토리 먼저 확보 (추측 금지)
SELECT COLUMN_NAME, DATA_TYPE
FROM   ALL_TAB_COLUMNS
WHERE  OWNER = 'SCM_MGR' AND TABLE_NAME = :tbl AND NULLABLE = 'N'
ORDER BY COLUMN_ID;
```

2. INSERT 의 **컬럼 목록 ↔ SELECT 식**을 **위치 기반 1:1** 로 대조한다.
   개수가 어긋나면 건너뛰지 말고 **오류로 드러나게** 한다(누락 0).
3. 이미 안전한 식(리터럴 / 기존 `NVL` / `SYSDATE` / 변수 / 숫자)은 건드리지 않는다.

## §4. 정정 작업 시 실제로 겪은 함정 (전부 실측)

| # | 함정 | 대응 |
|---:|---|---|
| 1 | INSERT 컬럼 목록 **뒤에 라인 주석**이 붙어 `) SELECT` 패턴이 안 맞음 → 28개 중 **23개 누락** | 파서를 **주석 인식형**으로 (`--` / `/* */` 건너뛰기) |
| 2 | 식 **마지막 줄에 라인 주석**이 있으면 `NVL(...)` 닫는 괄호가 주석에 먹힘 | 닫는 괄호를 **다음 줄로** 내린다 |
| 3 | 치환 시 **후행 개행 소실** → 항목 끝 주석이 다음 항목을 삼켜 코드가 주석 처리됨 | 선행·후행 공백(개행 포함) **보존** 필수. 정정 전후 **라인 수 대조** |
| 4 | `split` 시 주석 안의 콤마로 오분할 | 최상위 콤마 분할기도 주석·문자열 리터럴 인식 |

## §5. 오탐 — 결함이 아닌 것 (고치지 말 것)

| 항목 | 근거 |
|---|---|
| `NVL(x, NULL)` | 동작상 no-op. 표시 결과가 AS-IS 와 같다. 무의미한 표기일 뿐 (DMF0044 77건) |
| `LIKE '%' \|\| p \|\| '%'` | Oracle `\|\|` 는 NULL 을 빈문자로 취급. 실측 `'%'\|\|NULL\|\|'%'` → `'%%'` 매치. **결함 아님** |
| `V_X := ''` | 대입이라 영향 없음 |

## §7. 판정 근거는 AS-IS 원문

정정 여부는 **AS-IS MSSQL 원문 대조로 확정**한다. 추측으로 고치지 않는다.

- AS-IS DDL 위치: `Doc/_legacy_source/DB_DDL/AsIs_LGCE_SCMDEV_SP{1~10}_DDL.sql` (SP별 라인 오프셋 존재)
- `ISNULL(x,'')` → 빈문자 치환 의도 → 정정 대상
- `ISNULL(x, 0)` 등 다른 기본값 → 그대로 유지
- AS-IS 에 대응이 없는 TO-BE 신규 구문 → TO-BE 의도로 판단
- **AS-IS 대응이 불명확하면 임의 판단하지 않고 보류로 보고**
