> **상위**: `anti-simplification.md` / hook #139(요구 대조 단위=하위문구) / hook #149(증상 재현 종결 게이트)

## §0. 배경 (실사고 — 2026-10-15 GAP 439, DMF0082 Current 외 버전 조회 불가)

| 단계 | 사용자 지정 | AI 행동 | 낭비 |
|---|---|---|---|
| 1 | "VERSION 선택 시 CURRENT 이외 버전 조회 안 됨" | FE `features/**` 전역 grep (타임아웃 2회) · 화면 폴더 탐색 | 대상 SP 도달 전 장시간 |
| 2 | "버전 뒤 '( )' 를 제외하고 조건에 넣어" | 계층 미확인 상태로 **FE 수정** | 이후 원복 |
| 3 | "VERSION_TYPE 이 아닌 VERSION_ID" | 팝업 VERSION_TYPE 축·SP 목록 조사 | 무관 축 조사 |
| 4 | "조회 PKG.SP 에서 제거, 사내오라클 테스트" | SP 재현 시 `p_item_id='ALL'` 입력 (FE 실전송값은 `''`) → `LIKE '%ALL%'` 로 **정상값까지 0건** → 무관한 0건 원인 추적 | 재현 실패 원인 추적 |

실제 보완 = `PKG_DMF0082.P_DMF0082_GET_MAIN_DATA` 버전 토큰 적재 **1문장**(L297). 사용자가 3회 재지시.

## §1. 근본원인

1. **요청 문장의 지정 대상을 추출하지 않고 화면 전체 흐름부터 추적** — 지정된 값·처리방식이 있었는데도 "어디서 오는가"를 처음부터 재구성.
2. **수정 계층(FE/BE/SP)을 임의 선택** — 확인 없이 가장 먼저 닿은 계층을 고침.
3. **재현 파라미터를 추정값으로 구성** — FE `setFilters` 의 실제 전송값(빈 값 `''` vs `'ALL'`)을 보지 않음.
4. **대조군도 0건인데 재현을 계속** — "문제값 0 / 정제값 N" 대조가 성립하지 않으면 재현 자체가 틀린 것인데 원인을 SP 내부로 추적.

## §2. 의무 (G153-1 ~ G153-5)

| # | 의무 | 판정 |
|---|---|---|
| G153-1 | **지정 대상 추출 먼저** — 요청에서 `대상 값/파라미터 · 위치(계층·객체) · 처리방식` 3요소를 첫 응답에 1줄로 적는다. | 3요소 미기재 착수 = 위반 |
| G153-2 | **지정 지점 직행** — 3요소가 특정돼 있으면 그 객체 원문(DB 는 hook #152 최신 원문)만 열고 수정. 화면 전체 흐름 재구성·전역 grep 선행 금지. | 지정 지점 외 탐색이 수정보다 앞섬 = 위반 |
| G153-3 | **계층 미지정 시 1줄 확인** — 위치가 특정되지 않았고 FE/SP 어느 쪽이든 고칠 수 있으면 추측 수정 금지, "SP L### / FE 파일 중 어디서 처리할지" 1줄 확인 후 착수. | 확인 없는 계층 선택 후 원복 = 위반 |
| G153-4 | **재현값 = FE 실전송값** — SP 직접 호출 재현은 FE store `setFilters`(또는 BE 로그)의 실제 파라미터를 그대로 사용. 특히 빈 값 `''` / `'ALL'` / NULL 구분, 테스트 사용자는 사용자 지정 계정(기본 `minyonglee1`). | 추정 파라미터 재현 = 위반 |
| G153-5 | **최소 대조 1쌍** — 재현은 "문제값 vs 정제값" 1쌍. **정제값도 0건이면 재현 무효** → SP 내부 추적 금지, 파라미터부터 재점검. | 대조군 0건 상태로 원인 추적 = 위반 |

## §3. 자기점검 (착수 3분 내)

- [ ] 첫 응답에 지정 대상 3요소(값·위치·처리방식)를 적었는가
- [ ] 지정 지점 원문을 수정 전에 연 것 외 다른 탐색을 하지 않았는가
- [ ] 계층이 미지정이면 1줄 확인을 받았는가
- [ ] 재현 파라미터가 FE 실전송값과 일치하는가 (`''`/`'ALL'` 대조)
- [ ] 대조군(정제값)이 0건이 아닌가
