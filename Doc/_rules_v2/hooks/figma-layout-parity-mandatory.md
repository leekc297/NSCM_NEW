# Hook — Figma 디자인 ↔ 구현 레이아웃 정합 (필수, PR 차단)

> 분류: 🆄 UI/화면 · 트리거: **T01(신규) · T01M(수정) · T11(Figma)** · 등급: ⭐⭐⭐ PR 차단
> 신설: 2026-06-26 (SYS0014 Group User 사고 — 구현이 Figma 디자인과 불일치인데 수정 시에도 레이아웃 미교체)

## §0. 배경 (사고)
- SYS0014 구현(2026-06-12)은 *상단 검색 + 상단행[Authority|GroupUser] + 하단행[Division|Plant|Customer]* 구조.
- Figma 프레임 `5934:143433` 디자인은 *상단 조건 없음 + 좌 GROUP(전체높이) + 우상 USER + 우하 DIVISION*.
- 사용자 투자(Figma SVG/MD 추출)에도 **구현이 디자인을 반영하지 않았고, 룰 수정 작업(T01M)에서도 레이아웃을 교체하지 않음** → 디자인 미적용 지속.
- 근본원인: ① 구현이 Figma MD보다 선행(역순) ② Figma↔구현 정합 강제 게이트 부재 ③ Figma MD 가 geometry만 보유(영역 배치 비명시).

## §1. 핵심 룰 (불변) — ⭐ 디자인 충실 구현 = **1순위** (사용자 명시 2026-06-26)
> "피그마 디자인이 있으면 그대로 구현하고, 피그마가 없으면 캡쳐이미지나 디자인 제공 파일을 현재 UI 표준을 지키면서 **그대로 구현하는게 첫번째**입니다. 디자인을 분석하고 다르게 생성하면 신뢰할 수 없습니다."

**구현은 제공된 디자인을 그대로 재현한다. 분석만 하고 임의로 다르게 만드는 것 = 신뢰 손상 = 금지.**
1. **Figma 있으면 → Figma 그대로** 구현 (영역 배치/그리드 수/명칭/버튼 위치/검색영역 有無 전부).
2. **Figma 없으면 → 캡쳐 이미지 / 제공 디자인 파일을 현재 UI 표준(공용 컴포넌트/룰) 지키면서 그대로** 구현.
3. **임의 추가/유지 금지**: 데이터 모델(SP/메타)에 N개 있어도 **디자인에 없는 그리드/버튼/필드는 만들지 않는다**. (예: SYS0014 — SP 가 unit D/P/C 3종 지원해도 디자인이 Division 1개면 Division 만.)
- **T01M(수정) 시 레이아웃 교체는 필수 항목** — 디자인과 현재 구현이 불일치하면 **레이아웃을 디자인에 맞게 교체**(기능만 고치고 방치 금지).
- T01(신규) 시 **디자인을 source 로 사용**(디자인-우선). 구현이 디자인보다 먼저면 사고 — 디자인 먼저 확보/참조.

> ⚠️ **디자인 원본 미확보 시 임의 구현 금지**: Figma node JSON/캡쳐를 못 받았으면 **추정 구현 대신 사용자에게 디자인 원본(재추출/캡쳐)을 요청**한다. 추정→사후 수정 반복 = 신뢰 손상.

## §1.5 적용 경계 — ⭐ Figma = 디자인 참조 only, **정책 판단 소스 아님** (사용자 명시 2026-07-14)
> "UI 분석 시, Figma 파일은 디자인 참조일 뿐, 정책에 대한 확정 Rule 은 아닙니다. Figma 를 보고 정책에 대한 판단은 진행하면 안 됩니다."

- 본 hook 의 "Figma 그대로" 의무는 **디자인/레이아웃 축 한정** (§2 영역 배치 6축 — 배치/분할/버튼 위치/라벨/검색영역 有無).
- **정책 판단에 Figma 사용 금지**: 권한/편집 규칙, 필수값, 기능 동작·프로세스, 데이터/메타 규칙, Validation, 콤보 값·기본값, Division 분기 등 **업무 정책은 Figma 에서 도출하지 않는다** (Figma 에 보이는 값·상태·항목 구성은 디자인 시점의 예시일 수 있음).
- **정책의 소스** = AS-IS 원소스(.cs/SP) 실측 + DB 메타 실데이터 + 화면별 분석서(8 MD/10시트) + **사용자 확정**. Figma 와 정책 소스가 충돌하면 → 정책 소스 우선 + 충돌 사실 보고.
- 분석서 작성(hook #105)에서도 동일: Figma 는 LAYOUT 시트 이미지·배치 참조로만 사용.

## §2. 정합 대상 (영역 배치 6축)
| 축 | 점검 |
|---|---|
| 1 상단 검색영역 | Figma에 조건 영역 有無 ↔ 구현 SearchArea 有無 (디자인이 "조건 없음"이면 SearchArea 제거) |
| 2 좌/우 분할 | 좌측 패널 ↔ 우측 영역 폭·존재 |
| 3 상/하 분할 | 각 컬럼의 상단/하단 grid 배치 |
| 4 영역별 컨텐츠 | 각 영역이 담는 grid/그룹 (좌=GROUP / 우상=USER / 우하=UNIT 등) |
| 5 버튼/툴바 위치 | Figma 버튼 영역 ↔ SubTitle/TitleArea 버튼 |
| 6 라벨 | Figma 영역 라벨 ↔ i18n 라벨 (node JSON 회복 시) |

## §3. PRE-WRITE (의무)
- [ ] 화면의 Figma MD(`Doc/_figma/screens/{ID}.md`) **존재 확인**. 있으면 **§5 레이아웃 구조 섹션을 읽고 영역 매핑표 작성**.
- [ ] 영역 매핑표: `Figma 영역(좌표) | 디자인 의도 | 구현 컴포넌트/위치 | 일치/불일치`.
- [ ] **불일치 행이 있으면 (T01M) 레이아웃 교체 작업을 범위에 포함**. (생략 금지 — 기능만 고치고 종료 금지)
- [ ] Figma MD 부재 시 → T11/Figma 추출(`fetch-figma.ps1`) 선행 권장. 추출 불가(rate-limit 등) 시 사유 명시 + SVG geometry(§1 rect)로 영역 배치 정합.

## §4. Figma 추출 MD 작성 표준 (actionable 의무)
Figma → MD 생성 시 **반드시 "레이아웃 구조(영역 배치)" 섹션 포함** — rect 좌표뿐 아니라 **영역별 의미(상단조건/좌/우상/우하 + 각 영역 컨텐츠 라벨)**를 명시한다. geometry-only MD 금지(비actionable).

## §5. 완료 게이트 (screen-completion-gate 연계)
- [ ] 영역 배치 6축(§2) 정합 — 불일치 0.
- [ ] (수정 작업) 레이아웃 교체 수행 또는 "이미 정합" 명시.
- [ ] 보고: `Figma 영역 ↔ 구현` 매핑표 + 정합 결과.

## §6. 안티패턴
- ❌ 기능(타입/권한/버튼)만 고치고 레이아웃은 디자인과 불일치인 채 방치 (← SYS0014 사고).
- ❌ Figma MD를 읽지 않고 구현 레이아웃 유지.
- ❌ "상단 조건 없음" 디자인인데 빈 SearchArea/검색필드 추가.
- ❌ geometry-only Figma MD 생성 (영역 의미 비명시).
