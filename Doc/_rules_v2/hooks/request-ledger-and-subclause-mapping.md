## §1. 절대 룰 (Hard Rules)

1. **요구 대조 단위 = 행이 아니라 하위 문구.** 원천 셀은 전문 덤프 후 ①②③/줄바꿈 단위로 분해해
   1행 1요구로 등재한다. 하위 1개만 이행하고 행 단위 "완료" 기록 금지 (기존 유령 룰의 성문화).
2. **단일 원장 = `Doc/단위테스트_보완대상/보완요청_원장.md`.** 문서·대화 어느 창구로 지정된
   보완요청이든 **받는 즉시 원장에 등재**한다 (채록 의무). 원장 밖의 요구는 게이트가 세지 못한다.
3. **⭐⭐⭐ 미적용 전제 (사용자 확정 2026-08-20)**: 등재 시 초기 상태는 무조건 `PENDING`.
   기존 문서의 '완료' 표기 승계 금지. `PENDING` → 다른 상태로의 전이는 **착수 시점 실측
   (코드 grep/DB SELECT/실행 증명) 근거를 근거 칸에 기입할 때만** 허용. 근거 공란인 비-PENDING
   행 = 게이트 FAIL. 사전 판단·기억·이전 세션 판정으로 SKIP 절대 금지.
4. **게이트 4중 FAIL**: 원장 행의 대사표 미편입 / PENDING 잔존 / '구현' 행 판정신호 실측 불일치 /
   원장↔대사표 상태 불합치 — 어느 하나라도 = 화면 완료 선언 불가.
5. **보류 소실 금지**: `USER-DECISION`(사용자 의사결정 대기)/`VISUAL`(육안 확인 필요) 은 FAIL 이
   아니라 **PASS 여도 리포트에 상시 목록 출력**된다. 완료 보고에 이 목록을 반드시 옮겨 적는다.
6. **사내/클라우드 2축 분리**: `사내` `클라우드` 열을 각각 기록. 클라우드=N 행은 상시 WARN 목록
   출력 + 완료 보고에 "클라우드 미반영" 행 명시 의무 (hook #126 ERROR 행 규약과 연동).
7. **룰 소급 대기 = RULE 행 유형**: 공용 유틸/신규 룰 신설 시 소급 미적용 화면 목록을
   `REQ:RULE-…` 행으로 원장에 등재 (갭⑤ — "작업 시점 적용" 정책의 분모 보존).

## §2. 원장 스키마 (정본)

9열 표 — 게이트(`asis_mapping_gate.py::parse_request_ledger`)가 그대로 파싱한다:

```
| ID | 출처 | 하위문구(분해 원문) | 대상 UI | 판정신호 | 상태 | 사내 | 클라우드 | 근거 |
```

- **ID**: `REQ:1ST-33-2`(1st xlsx No.33 의 ②) / `REQ:2ND-07-1` / `REQ:CHAT-YYYYMMDD-n`(대화 지정) /
  `REQ:RULE-…`(룰 소급). ID 중복 = 파서 FAIL.
- **대상 UI**: MNU_ID (복수 허용, `ALL`=전 화면 공통 — Common 행은 `=COMMON:UC-nn` 위임 표기로
  각 화면 COMMON 축이 판정을 담당, 이중 판정 방지).
- **판정신호 문법**: `FE:<rx>`(페이지 폴더 grep) / `SHARED:<rx>`(nscm-fe 전체 — 공용 유틸 소비 축) /
  `EV:<repo상대경로>::<rx>`(SP 마커·DDL 증적 파일) / `!FE:<rx>`(0건이어야 PASS — 제거 요구),
  `;;` 로 복수. 미정이면 `(미정 — 사유)` (실측 스킵되며 근거 칸으로만 판정 불가 → PENDING 유지).
  정규식에 `|` 금지 (md 표 셀 파괴).
- **상태 enum**: `PENDING / APPLIED / VERIFIED / USER-DECISION / VISUAL / EXCLUDED` — 이 외 = 파서 FAIL.
- 미분해 등재 허용: `[분해 미완]` 접두 + PENDING (분모 우선 원칙 — 해당 UI 착수 시 분해 의무).

## §3. 절차 (T01M ⓪단계)

1. **채록**: 지정 원문(셀/대화) 전문 덤프 → 하위문구 분해 → 원장 등재 (전부 PENDING).
2. **편입**: `python _artifacts/_diagnostics/asis_mapping_gate.py --init <분석md...> <페이지폴더> --menu {MNU_ID}`
   → 대사표에 `## 보완요청(REQ) 축` 섹션 생성 (기입값 보존·멱등).
3. **실측 전이**: 행별 판정신호 확정 → 실측 → 원장 상태/근거/사내/클라우드 갱신 + 대사표 REQ 행
   상태 기입 (APPLIED·VERIFIED↔구현+위치 / EXCLUDED·USER-DECISION·VISUAL↔제외·해당없음+사유).
4. **게이트**: `--check <페이지폴더> --requests-only --menu {MNU_ID}` (러너 `[10/10]` 섹션이 자동 수행).
   완료 선언 = 러너 10섹션 리포트 첨부 + 보류·클라우드N 목록 전기.

## §4. 게이트 자기검증 (음성 대조군 — hook #126 §5)

게이트 신뢰 전 3종 FAIL 재현 의무: (a) 원장 행 1건 대사표 누락 (b) PENDING 1건 잔존
(c) 판정신호 훼손 — 사본(`--requests` override + `--out`)으로 재현 로그 확보 후 본선 적용.
