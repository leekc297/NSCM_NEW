# issue-log-daily-workflow — 일일 이슈목록 정리·룰 후보 편입 절차

> **트리거**: 사용자가 "이슈목록 정리", "오늘 이슈 정리해줘", "이슈 룰 반영" 등을 요청할 때.
> **목적**: Claude Code 개발 후 발생 이슈를 일일 단위로 MD 정리하고, 룰 후보를 안전지대 피드에 누적한다.
> **성격**: 문서 hook(guide). 자동 차단(enforced) 아님 — AI 가 읽고 지킨다.

| 시트 / 헤더 | 시트명 `이슈목록`, 헤더 행 5 (C5~S5), 데이터 행 6부터 |

## 컬럼 정의 (17열)

`No.` / `브랜치 버전` / `확인일자` / `1Dept` / `2Dept` / `화면명(3Dept)` / `화면ID` / `구분` / `확인자` / `이슈사항` / `처리내역` / `스크린샷 Link` / `처리 담당` / `처리여부` / `머지여부` / `처리일자` / `비고`

## 절차 (7단계)

1. **변경 감지**: `Doc\issue\이슈목록관리.xlsx` 의 크기·수정시각(또는 해시)을 직전 처리분과 비교. **동일하면 즉시 종료**(작업 없음).
2. **전수 파싱**: openpyxl `data_only=True` 로 `이슈목록` 시트 전 행을 읽는다. 셀 줄바꿈·코드 원문을 **요약·생략 금지** (anti-simplification). 빈 행 스킵.
3. **MD 작성** — `_analysis/이슈목록_{날짜}.md`:
   - 헤더(원본 경로·목적·총 건수·생성일)
   - §1 요약 통계 (총/구분별/처리·머지 완료/화면ID별 분포)
   - §2 이슈 일람표
   - §3 이슈 상세 (No.별, 이슈사항·처리내역 원문, 코드는 ```ts/```tsx)
   - §4 룰 후보 표 (처리내역 보유 이슈 → 재사용 규칙: 출처 No / 화면ID / 룰 후보 / 트리거)
   - §5 후속 조치 (DB 정비·상세 미기재·머지 대기·근본 미해결)
4. **검증**: MD 상세 섹션 수 == Excel 데이터 행 수 (누락 0건 필수). 불일치 시 보완 후 재검증.
5. **룰 후보 편입**: `issue-feed-rules.md` 의 `<!-- DAILY-APPEND-MARKER -->` **바로 위**에 신규 날짜 블록 **추가만**. 기존 블록 수정·삭제 금지. ⚠️ 정식 룰 문서(_tobe, 타 hook) 자동 수정 금지 — 본 피드에만 적재.
6. **승격(사람 검토)**: 피드의 `후보` 중 정식 룰로 승격할 항목만 사람이 해당 hook/룰로 이관, 상태를 `편입완료` 로 표기.
7. **보고**: MD 파일 공유 + 신규 이슈 수·룰 후보 수·미처리 수 요약. 전일 대비 신규 강조.

## 참고 — Claude Code vs Cowork 스케줄

- Cowork 의 스케줄 작업은 본 절차를 **자동 트리거**할 수 있으나 Claude Code(CLI)와 별개다.
- Claude Code 는 본 hook 을 읽고 동일하게 처리한다. 자동 실행 대신 사용자 요청 시 수행.
