## §1. 근본원인 3 (이번 감사 실측)

1. **증상 → 최근접 기존 로직 귀속**: 신고 문구에서 키워드(QTY)를 뽑아 "관련 로직이 있는가"를 찾고, 있으면 그 로직의 실존·단위 양성으로 종결. **신고된 행동(체크해도 건수 동일)을 재현하는 단계가 통째로 생략**된다.
2. **직전 건 원인 프레임 이월**: -8 이 "클라우드 구본 회귀"로 판명되자 -12/-13 도 같은 프레임(사내 정상·클라우드 형상)으로 패턴매칭 — 건별 재현 없이 일괄 귀속. (-13 은 사내에서도 재현되는 변환 결함이었다.)
3. **"존재 실측"을 "실측"으로 오독**: 원장 원칙("전이는 착수 시점 실측 근거만")의 '실측'을 코드/룩업 **존재 확인**으로 충족했다고 간주. 존재는 동작을 증명하지 않는다 (-13: 필터 블록 실존 + 무효).

## §2. 의무 — 종결 게이트 6항

```
[G149-1] 재현 먼저: 상태 전이 전제 = 신고 증상의 재현 실측.
         신고 시나리오·수치 그대로(가능한 한 동일 조건), 재현 환경 명시(사내/클라우드/로컬).
         재현 실패 = 그 자체가 1급 정보 → 환경·데이터 축 진단으로 전환. "관련 로직 실존" 종결 ⛔.
[G149-2] 해소 실측: 정정 후 동일 시나리오 재실행 → 증상 소멸 실측. 근거 칸에 「재현: …」「해소: …」 2축 필수.
[G149-3] 존재 ≠ 동작: 코드 블록·룩업·배선의 실존 확인은 전이 근거로 불인정.
         인정되는 근거 = 기능 실측만 (신고 시나리오 재현/해소 · SQL 게이트 양성+음성 쌍 · 러너/직접 호출 왕복).
[G149-4] 신고 환경 종결: 클라우드 신고 건은 신고 환경 해소 확인(사용자 실측) 전 '클라우드 Y' ⛔.
         APPLIED = "사내 해소 실측 완료 + 신고환경 대기" 로 의미 한정 — 종결 아님. VERIFIED 도 재현·해소 2축 충족 시만.
[G149-5] 원인 프레임 이월 금지: 직전 건의 원인(클라우드 회귀 등)을 다음 건에 가정으로 쓰지 않는다. 건별 G149-1 부터.
[G149-6] 종결 보고 형식: 「재현 → 원인 → 정정 → 해소」 4요소. 하나라도 없으면 "완료" 선언 금지 —
         빠진 요소를 "미실측" 으로 명기하고 보류 상태(PENDING/USER-DECISION)로 남긴다.
```
