## §0 배경 — 실사고 (2026-08-11, DMF0049 "저장하면 같은 행이 하나 더")

사용자가 저장 후 재조회에서 **같은 행이 2개** 보인다고 보고. div40 조회가 170행 → **171행**이 되고
재조회해도 유지됐다(멱등 아님). E2E 왕복 FAIL 로도 재현(같은 식별자에 값 있는 행 + 빈 유령 행).

**근인 = 조회가 Oracle PIVOT 이라는 사실**:
```
PIVOT ( SUM(QTY) FOR YYYYMM IN (...) )   -- 암묵 GROUP BY = SELECT 목록의 "나머지 전 컬럼"
```
⇒ **저장이 컬럼 하나만 원장과 다르게 써도 그 월만 그룹이 갈라져 표시 행이 2개**가 된다.
원인은 2중이었고, 성격이 달라 조치도 달랐다:

| # | 원인 | 성격 | 조치 |
|---|---|---|---|
| 1 | 저장 INSERT 가 `'' AS DOM_EXP / '' AS INCOTERMS / '' AS PLANT_SITE_ID` 하드코딩. **AS-IS MSSQL 도 똑같이 `''`** 지만 MSSQL `''`=빈문자열 / **Oracle `''`=NULL** → 원장 센티널 `'-'`(209,671행)와 그룹 분리 | **방언 결함** | `'-'` 로 정정 + 누적 NULL 93행 backfill |
| 2 | 저장이 `DEPT_NAME` 을 **항상 현재 마스터 룩업값으로 덮어씀** — AS-IS SP 도 동일 CASE 구조 = **파리티** | 파리티 (SP 무수정) | **원장 정규화**(옛 명칭 2,532행 → 현재 마스터값) |

## §1 원칙 — "저장 후 재조회가 저장 전과 같은 행 집합이어야 한다"

**저장 멱등성**: 값 편집(M) 저장 → 재조회했을 때
1. **행 수가 늘거나 줄지 않는다** (170 → 171 = 결함)
2. **화면 식별자 조합이 유일하다** (예: DATA_SEQ×MEASURE 당 1행)
3. 편집한 셀 외의 표시 값이 바뀌지 않는다

이를 깨는 3대 계보:

### 1-A. 센티널 방언 (MSSQL `''` → Oracle NULL)
- 저장 SP 의 `'' AS <컬럼>` 은 Oracle 에서 **NULL 기입**이다. 조회 그룹 축에 있는 컬럼이면
  형제 행(센티널 `'-'`)과 갈라진다.
- ⭐ **센티널 값은 "컬럼별 원장 실측 분포"로 결정한다** — 일괄 `'-'` 금지:
  ```
  DOM_EXP / INCOTERMS / PLANT_SITE_ID : '-' 209,671 vs NULL 93   → '-' 가 정본
  PROJECT_NAME                        : 전량(209,764) NULL        → '' 유지 ('-' 로 바꾸면 반대로 갈라짐)
  ```
- AS-IS 원문이 `''` 라는 사실은 **면죄부가 아니다** — 방언 차이는 TO-BE 가 흡수해야 할 변환 의무다
  (hook #119 계보. 같은 날 `SOLDTO_CODE` 도 동일 정정 — 마커 SOLDTO-SENTINEL / PIVOT-SENTINEL).

### 1-B. 파생 컬럼의 세대 불일치 (저장이 마스터 현재값으로 덮어쓰는 컬럼)
- `DEPT_NAME` 처럼 저장 시 **룩업 현재값**으로 재산출되는 컬럼은 설계상 "기록 시점 스냅샷"이 아니라
  **현재 이름**이다. 원장에 옛 명칭이 남아 있으면 **저장한 월만** 새 이름이 되어 갈라진다.
- 조치는 SP 가 아니라 **원장 정합**(마스터 기준 일괄 정규화)이다 — 단 스냅샷 보존이 업무 요구인지
  사용자 확인 후. (AS-IS 도 덮어쓰는 파리티 로직이면 SP 는 손대지 않는다.)

### 1-C. 검증 도구가 가해자가 되는 경로 (PIVOT 표시값 되쓰기)
- PIVOT 조회의 셀 값은 **SUM(표시값)** 이다. E2E/검증이 그 값을 payload 로 되쓰면 단일 원장 행에
  집계값이 내려앉는다. 게다가 저장 SP 가 payload 에 없는 컬럼을 보강하므로 **"원복" 해도 원상태가 아니다**.
- ⇒ 이런 화면은 E2E 시나리오에 **`modify_safe: False`**(+ `insert_delete_safe: False`) 를 명시하고
  사유를 리포트에 WARN 으로 남긴다(조용한 생략 금지). 원장 직접 검증이 필요하면
  `save_mode: 'insert_first'`(러너가 만든 행 위에서만 왕복) 설계로 전환한다 — DMF0044 선례.

## §2 완료 선언 전 의무 검증 (게이트 G9 연동)

저장 경로가 있는 화면은 완료 선언 전에 다음을 **실측**으로 남긴다:

| # | 검증 | 판정 |
|---|---|---|
| 1 | 조회 SP 가 PIVOT/GROUP BY 인가 — 그렇다면 **그룹 축 컬럼 목록**을 산출했는가 | 목록 없이 "확인했다" = ERROR |
| 2 | 저장 SP 의 INSERT/MERGE 가 그룹 축 컬럼에 쓰는 값 = 원장 분포와 일치하는가 (`'' `→NULL 전수 grep) | 불일치 1건 = FAIL |
| 3 | **저장 전/후 조회 행수 동일 + 화면 식별자 조합 중복 0** (실호출) | 행수 증가 = FAIL |
| 4 | 저장이 payload 밖 컬럼을 보강하는가 — 보강 컬럼이 그룹 축이면 원장 세대 일치 확인 | |

⚠ §0 사고는 **기존 8게이트+9섹션 종합 PASS 상태에서** 사용자가 발견했다 — #3 이 없으면 게이트는
이 계보를 영원히 놓친다.

## §3 진단 시 함정 (실측 계보)

- **이력 대조는 반드시 `VERSION_NO` 까지 건다** — 빼면 다른 버전의 이력이 섞여
  "원본 값" 을 오판한다(2026-08-11 실측: 타버전 '기타매출' 이력 31건이 섞여 보임).
- "원장 무손상" 판정은 **값·부수 컬럼까지 형제 행과 대조**한 뒤에만 말한다 — DELETE→INSERT 경로는
  CREATION_DATE 가 갱신되므로 시각만 보고 "새 행이 생겼다/안 생겼다" 를 판단하면 틀린다(당일 실제 오판 1회).
- 중복 표시 행의 원인 특정은 **두 행의 차이 컬럼 diff** 가 가장 빠르다(전 컬럼 비교 → 다른 컬럼만 출력).
