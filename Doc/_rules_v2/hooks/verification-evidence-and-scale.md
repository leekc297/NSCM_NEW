## §0. 증상 → 원인 → 조항

| 증상 | 원인 | 조항 |
|---|---|---|
| 대사표에 `구현` 인데 코드에 그 로직이 **없다** | AS-IS 만 보고 채우고 TO-BE 코드로 되짚지 않음 | §1 |
| FAIL 이 "오탐"으로 재분류되며 **기대값이 실측값으로 바뀜** | 존재하지 않는 규약을 근거로 인용 | §2 |
| 삽입이 실패했는데 **삭제가 PASS** 로 찍힘 | 사전 상태(0행)와 삭제 결과(0행)를 구분 못 함 | §3 |
| 소량은 되는데 실사용 규모에서 터짐 | 테스트가 1행 단위 | §4 |
| 행 단위로는 "미보완 0" 인데 실제로는 미적용 | 분기·하위문구 단위로 안 봄 | §5 |

다섯은 **같은 병**이다 — 근거 없이 초록불을 만든다.

## §1. `구현` 주장은 **대조 가능한 근거**를 달아야 한다

### 실사고 (2026-08-22)

DMF0082 `__asis-mapping__.md` 에 이런 행이 있었다:

```
| M-22 | MKT_FCST / InsertRow(포커스 행 없음)
       | ForecastPrice.tsx `handleInsert` — 시드 없으면 MEASURE='MKT_FCST' | — | 구현 |
```

**분석은 정확했다.** AS-IS else 분기(`.cs:2674`)를 정확히 집어냈다. 그런데 **코드에는 그 조건문이
존재한 적이 없었다** — `MEASURE: ''` 한 줄이었다. 분석한 것을 구현하지 않은 채 `구현` 이라 적었고,
그 거짓 기록이 여러 번의 재점검을 통과했다. 사용자가 화면에서 직접 발견할 때까지.

### 의무

`상태 = 구현` 인 행의 **구현 위치 셀**에는 다음 중 최소 하나가 있어야 한다.

| 형태 | 예 | 검사 |
|---|---|---|
| 파일:라인 | `ForecastPrice.tsx:507-511` | 파일 실존 + 라인 범위 |
| 백틱 심볼 | `` `handleInsert` `` | 그 파일에 심볼 실존 |
| **백틱 리터럴** | `` `'MKT_FCST'` `` | **그 파일에 리터럴 실존** ← 핵심 |

⭐ **리터럴 축이 핵심이다.** M-22 는 파일도 심볼도 실존해서 파일·심볼 검사를 전부 통과한다.
**리터럴 대조만이** 거짓 `구현` 을 잡는다.

### 게이트

```
python _artifacts/_diagnostics/asis_mapping_evidence/verify_mapping_evidence.py <__asis-mapping__.md>
  → FAIL 0 · 근거 공란 0   (미달 시 화면 종료 선언 금지)
```

- 자연어 서술만 있고 인용이 없으면 `UNVERIFIABLE` 이다. **PASS 가 아니다.**
- 이 도구는 "인용한 근거가 실재하는가" 만 본다. **동작 동등성은 사람이 본다.**
  즉 `PASS` = "거짓 인용이 아니다" 이지 "AS-IS 와 같다" 가 아니다.

## §2. 테스트 기대값을 **실측값으로 바꾸지 않는다**

### 실사고 (2026-08-08 → 2026-08-22 적발)

`crud_roundtrip_dmf0082.py` 의 삭제 판정이 이렇게 바뀌어 있었다:

```python
# SP L11762 주-합계 재산출 규약: 같은 주에 다른 수요가 남아 있으면 'D' → 'M' 으로 재산출되어 행 유지가 정상.
d_expect = 0.0 if wk_other == 0 else float(ad[0])      # ← 기대값 = 실측값
d_ok = abs(float(ad[0]) - d_expect) < 0.001            # ← 항상 PASS
```

인용된 근거를 실제로 읽어보면:

```
L11760  SELECT MIN(BASIS_START_DATE), MAX(BASIS_END_DATE)
L11762  FROM SCM_MGR.SCM_SYS_CALENDAR_M M          ← 52주 구간 계산. 재산출과 무관
```

진짜 재산출은 **L12739~12748** 이고 적용 범위가 한정돼 있다:

```
L12744  WHERE B.MEASURE = 'LOC' AND B.ACTION <> 'I'
L12748  WHERE A.MEASURE = 'LOC' AND A.ACTION <> 'I';
```

러너의 `pick()` 은 **`MEASURE='MKT_FCST'`** 만 고른다 — 그 예외는 **적용될 수 없었다.**
결과: "수요 measure DELETE 미구현"이라는 실결함이 2주간 초록불로 통과했다.

### 의무 — FAIL 을 오탐으로 재분류하려면 3가지를 모두 적는다

| # | 요건 | 위 사고에서 |
|---|---|---|
| ⓐ | **코드 라인 인용** (`파일/객체:라인`) | O — 다만 L11762 는 엉뚱한 문장 |
| ⓑ | **적용 범위 명시** (measure / division / ACTION 등) | ⛔ 누락 — 실제로는 `LOC` 전용 |
| ⓒ | **인용 라인 실존 확인** (원문을 실제로 출력해 붙일 것) | ⛔ 미수행 |

ⓑ 가 이 사고의 급소다. 규약이 존재하더라도 **범위가 내 테스트 대상과 겹치지 않으면 근거가 아니다.**

⛔ **금지**: 기대값에 실측값을 대입하는 모든 형태
(`expect = actual`, `expect = actual if cond else 0`, `assert actual == actual` …).
기대값은 **사양에서 나온 고정값**이어야 한다.

## §3. **선행 조건이 성립하지 않으면 판정하지 않는다** (PASS 아님, 판정불가)

### 실사고 (2026-08-22)

같은 러너의 40 축:

```
[I] SAVE I=7   → 'Model*: … Cell Prod Site* 를 Common으로 등록 할 수 없습니다.'   ← 삽입 실패
[I] 원장 후 QTY=0 rows=0
[D] SAVE D     → SUCCESS
[D] 원장 후 QTY=0 rows=0   → PASS                                              ← 거짓 PASS
```

원장이 **처음부터 0행**이면 "삭제됨"과 구분되지 않는다. 삽입이 실패했는데 삭제가 통과로 찍혔다.

### 의무

- `D` 판정 전에 **`I` 로 원장에 행이 생긴 것(rows=1)** 을 확인한다. 미성립이면 `None`(판정불가).
- 조회 결과를 키로 쓸 때 **그 키가 저장에 유효한지** 먼저 확인한다.
  (위 사고 원인: GET 이 `CELL_PROD_SITE_ID` 를 안 돌려줘 러너가 공란을 보냈다.)
  유효 후보는 **원장 실키**에서 뽑는다 — 원장에 있는 조합은 검증을 통과한 적이 있다.
- 종합 판정에 `판정불가` 가 있으면 **완료 선언 금지**. 후보를 바꿔 다시 성립시킨다.

정본 도구: `_artifacts/_diagnostics/_dmf0082_delete_proof_20260822.py`
(원장 실키 후보 순회 → I 성립 확인 → D 판정 → 정리, + 설계 의도 회귀 축).

## §4. CRUD 규모 축 — **SIZE 10,000 까지** 테스트한다

> 사용자 확정 2026-08-22: "CRUD 규모는 최대행수로 하면 너무 양이 많으니 **SIZE 기준 (10,000)** 까지의
> 테스트를 진행하면 됩니다."

### 왜 필요한가 — 실사고

DMF0082 저장이 **168행**에서 전면 실패했다:

```
ORA-20001: ORA-06502 … 문자열 버퍼가 너무 작습니다
ORA-06512: "SCM_MGR.PKG_DMF0082", 11399행
```

`V_PROC_INPUT VARCHAR2(4000 CHAR)` 에 24개 파라미터를 통째로 JSON 으로 담는데, 파라미터는 행 수만큼
`'^'` 로 이어붙인 문자열이다. `p_scm_site_id` 하나가 3,863자였다. **1행 테스트로는 절대 안 잡힌다.**

### 의무

| 항목 | 기준 |
|---|---|
| 규모 축 | **저장 페이로드 SIZE 10,000자** 까지 (최대 행수 아님) |
| 측정 대상 | 각 `'^'` 연결 파라미터의 길이 · 그 합 |
| 판정 | SIZE 10,000 에서 **저장 성공 + 원장 delta 일치** |
| 실패 시 | 버퍼·타입 한계를 코드에서 확인 (CLOB / 선절단 / 분할) |

⚠ 규모 실패는 **프로시저 시작부**에서 터질 수 있다 — 그러면 **아무것도 저장되지 않는다.**
"일부만 저장됨"이 아니라 "전건 실패"로 나타나므로, 다른 화면 증상("저장했는데 조회에 안 보임")과
같은 원인일 수 있다. 규모 결함 1건이 여러 증상으로 신고된다.

## §5. 대사표 대조 단위 = **행이 아니라 분기·하위문구**

AS-IS 한 항목이 `IF/ELSE` 로 갈리면 **분기마다 한 줄**로 적는다. 행 하나에 "구현"이라 적고
분기 하나만 확인하는 것을 금지한다.

### 실사고

INSERT 기본값이 AS-IS 와 달랐다. AS-IS `.cs:2674` 는 **포커스 행 유무로 갈린다**:

```
포커스 행 있음 → 그 행의 값 복사
포커스 행 없음 → MEASURE='MKT_FCST', CURRENCY 미설정      ← 이 분기가 미구현
```

대사표는 행 단위로 `구현` 이었고, 실제로는 **else 분기가 없었다.**

### 의무

- 분기 특정: `파일:라인` 은 **그 분기의 라인**을 가리켜야 한다 (조건문 시작 라인 아님).
- **대사표 공란 0** — `상태` 와 `구현 위치` 중 어느 쪽도 비우지 않는다.
  미구현이면 `미구현` 이라 적고 사유를 남긴다. 공란은 §1 게이트에서 FAIL 이다.
- 요구가 ①②③ 하위문구로 쪼개지면 **문구마다 한 줄** ([[requirement-subitem-granularity]]).
