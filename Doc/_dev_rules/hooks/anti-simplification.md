# Hook — Anti-Simplification (작업 단순화 절대 금지 룰)

> ⚠️ **이 룰은 다른 모든 룰을 압도하는 최우선 룰입니다.**
> AI 가 속도·편의·토큰 절약을 이유로 작업을 단순화하는 행위를 **금지**합니다.
> 위반 시 결과는 잘못된 산출물로 직결되며, 이는 **도구의 신뢰성 손상 → 사용 중단** 으로 이어집니다.

---

## §0. 배경 (사용자 명시 — 2026-05-22)

> "원소스를 읽어서 sp 사용분을 모두 추출해달라는 요청이였는데, 무슨 이유로 일부만 추출한건가요?
> 제가 요구한 사항에 대해서 임의로 일을 간소화하고 누락한 원인이 무엇인지 알고 싶어요?"
>
> "강력한 Rule 로 전체적인 작업에 대한 속도문제로 일을 단순화 하는 일은 절대 하지 않도록 hook 파일로 정의해주세요.
> 단순화 해서 잘못된 결과나 산출물을 도출하면 그건 신뢰성만 손상시키고, 클로드를 사용하지 않게 되는 결과를 이어질거에요."

**과거 위반 사례 (실제 발생, 2026-05-21~22):**

| 사례 | 사용자 요구 | AI가 한 단순화 | 결과 |
|---|---|---|---|
| v7.3 SCP/SSP/FP 분석서 | DM 수준 13시트 모두 채움 | 메타 추출기 자동 + 13시트 빈칸 다수 | xlsx 빈 시트 다수 → 재작업 |
| Screen_POPUP_SP_Tables_Matrix.xlsx | 모든 SP를 원소스에서 추출 | `FoxDataRequest("...")` 단일 regex 만 사용 | 변수/헬퍼/POPUP/.foxml SP 누락 → 재작업 |
| SCP/SSP/FP analysis.md | 화면별 .cs 전체 Read | 메타 기반 자동 채움 | 빈 칸 다수, 위반 마킹 |
| **DMF0020 SQL #1 (2026-05-22)** | 정확한 DDL 기준 INSERT | DDL 컬럼명을 추측 (UPPER_MNU_ID, MNU_LVL) | ORA-00904 — 재작업 |
| **DMF0020 SQL #2 (2026-05-22)** | 정확한 DDL 기준 INSERT | 다른 테이블 컬럼명 일반화 (USE_YN → SHEET_COLUMNS) | ORA-00904 — 재작업 |
| **DMF0020 SQL #3 (2026-05-22)** | DDL 정확 반영 | DDL 봤지만 **NOT NULL/DEFAULT 정책 미검증** (LAST_UPDATED_BY 누락) | ORA-01400 — 재작업 |

**누적 영향:** AI 신뢰도 손상, 같은 작업 재반복으로 사용자 시간 낭비.

**3중 단순화 패턴 (DMF0020 SQL 3건 공통 분석)**:
1. 컬럼명을 **다른 테이블 패턴** 으로 일반화
2. 첫 INSERT 1줄을 작성하고 N줄을 **복사-반복** (오류 N 배 증폭)
3. **DDL 의 NOT NULL/DEFAULT 정책** 까지 cross-check 없이 "DDL 봤다" 자칭

## §1. 절대 금지 (Hard Rules)

### 1.1 정규식·패턴 추출

| # | 금지 행위 |
|---:|---|
| 1 | ❌ "원소스에서 X를 모두 추출" 요청에 **정규식 패턴 1개**만 사용 |
| 2 | ❌ 변수에 담긴 값 / 상수 / 필드 / 헬퍼 호출 미고려 |
| 3 | ❌ 직접 호출 패턴만 잡고 간접 호출(BIZ Layer, util 클래스) 무시 |
| 4 | ❌ 추출 결과의 누락을 **자체 검증 없이** 산출물로 제공 |

### 1.2 자동화·일괄 처리

| # | 금지 행위 |
|---:|---|
| 5 | ❌ 자동화 1회 통과 결과를 검증 없이 채택 |
| 6 | ❌ "메타 자동 생성" 으로 빈 시트 다수 산출 (v7.4 §16 위반) |
| 7 | ❌ 화면별 .cs/.Designer.cs **전체 Read 생략** + 메타만 추출 |
| 8 | ❌ 시간/토큰 절약을 위해 일부 화면만 진행하고 나머지 SKIP |

### 1.3 검증·Cross-check

| # | 금지 행위 |
|---:|---|
| 9 | ❌ Cross-check 없이 산출물 제공 (기존 자료 ↔ 신규 산출물 비교 미실시) |
| 10 | ❌ 기존 분석 자료 (`02_Endpoints_Inventory.xlsx`, `_phase{1~4}` 등) **미활용** |
| 11 | ❌ 누락 가능성 검토 없이 "완료" 보고 |
| 12 | ❌ "샘플 1건 확인 후 전체 적용" — 샘플 검증만으로 전체 신뢰성 보증 |

### 1.4 ⭐ DDL Cross-check (2026-05-22 신설 — DMF0020 SQL 3중 사고 반영)

DDL 을 참조하는 SQL DML 작성 시 **5층 cross-check 의무**:

| # | 금지 행위 (= 단순화) |
|---:|---|
| 13 | ❌ "DDL 봤다" 자칭 후 컬럼명만 확인하고 끝 |
| 14 | ❌ DDL 의 **NOT NULL** 컬럼 누락 (INSERT 시 ORA-01400) |
| 15 | ❌ DDL 의 **DEFAULT 정책** 무시 (DEFAULT 없는 NOT NULL 컬럼을 생략 → NULL 위반) |
| 16 | ❌ 다른 테이블 패턴을 **추측으로 일반화** (예: A 테이블의 DEFAULT 정책을 B 테이블에 적용) |
| 17 | ❌ INSERT 1줄 작성 후 N줄 **복사-반복** — 첫 줄 오류 시 N 배 증폭 |
| 18 | ❌ 다층 위반 (컬럼명 + NOT NULL + DEFAULT 3중) 중 1~2 만 정정 후 재제출 |

**의무 (DDL 참조 SQL 작성 시 모두 필수)**:

```
[필수 1] DDL Read 시 다음 5층 모두 기록:
  ① 정확한 컬럼명 (대소문자 + 약어 OFF — 'UPPR_MNU_ID' vs 'UPPER_MNU_ID')
  ② 데이터 타입 (VARCHAR2(N), NUMBER, DATE 등)
  ③ NOT NULL 여부
  ④ DEFAULT 절 존재 여부 + DEFAULT 값
  ⑤ CHECK / FK / UNIQUE 제약

[필수 2] INSERT 컬럼 목록 작성 시:
  - 모든 NOT NULL + DEFAULT 없는 컬럼 → **반드시 명시**
  - DEFAULT 있는 NOT NULL 컬럼도 명시 권장 (DB 마이그레이션 시 DEFAULT 정책 변경 위험)
  - "표준 4 컬럼" (CREATED_BY / CREATION_DATE / LAST_UPDATED_BY / LAST_UPDATE_DATE) 은
    **테이블 무관 항상 4개 모두 명시** (NSCM 표준)

[필수 3] 다중 INSERT 작성 시:
  - 첫 INSERT 1줄 완성 + DDL 5층 cross-check 통과 후 → 나머지 N-1줄 복사
  - 첫 줄 검증 단계 없이 N줄 일괄 작성 금지

[필수 4] 다층 사고 정정 시:
  - 동일 BLOCK 안의 모든 INSERT 를 **한 번에** 검증
  - 컬럼명 정정 → NOT NULL 확인 → DEFAULT 확인 3 단계 모두 통과 후 제출
  - 1차 정정 → 2차 정정 → 3차 정정 의 **반복 금지** (한 번에 모두 catch)

[필수 5] DDL 1차 소스 위치 명시:
  - INSERT 위에 `-- DDL: 02_GTT_OTHER_part4.sql:LLLL` 주석 의무
  - 다른 작업자/AI 가 검증 시 동일 DDL 위치 참조 가능
```

**Cross-check 자동 SQL** (선택, 운영 환경):
```sql
-- INSERT 작성 직후 자기 검증: 누락된 NOT NULL 컬럼 발견
SELECT COLUMN_NAME, NULLABLE, DATA_DEFAULT
  FROM USER_TAB_COLS
 WHERE TABLE_NAME = '대상_테이블'
   AND NULLABLE = 'N'
   AND DATA_DEFAULT IS NULL
   AND COLUMN_NAME NOT IN ('내가 INSERT 한 컬럼들');
-- 결과 0 행 이어야 통과
```

## §2. 의무 (Hard Requirements)

### 2.1 추출·분석 작업의 의무

```
[필수 1] 사용자가 "모두 추출" 요청 → **다중 패턴 적용**:
  - 직접 호출 패턴 (예: 정규식 1)
  - 변수에 담긴 값 (변수 정의 추적)
  - 상수/필드 (예: const, readonly)
  - 간접 호출 (helper class, util, BIZ Layer)
  - XML/JSON 매핑 파일 (.foxml, .json 등)
  - 부모 클래스/POPUP 의 호출도 포함

[필수 2] 기존 분석 자료 우선 활용:
  - 전 도메인 인벤토리는 _phase1~2 자료 우선 신뢰
  - 화면별 분석서는 _screens/* xlsx 의 6_APIEndpoint 시트 신뢰
  - SP 본문은 DB_DDL/AsIs_LGCE_SCMDEV_SP*_DDL.sql 정확 위치 추적
  - "이미 분석된 자료" 가 있으면 그것을 마스터로 활용

[필수 3] Cross-check 의무:
  - 신규 산출물 vs 기존 분석 자료 (예: 6_APIEndpoint 시트) 자동 비교
  - 차이 화면 검출 → 원인 분석 → 보완 후 재산출
  - 차이 0건 또는 명확한 사유 (예: 기존 분석서 누락) 가 있어야 산출

[필수 4] 누락 검증:
  - 산출물에 "추출 누락 없음" 을 보장할 수 없으면, **추출 한계를 명시**
  - 예: "이 매트릭스는 직접 호출 (FoxDataRequest) 만 포함합니다. 간접 호출 미포함"
  - 사용자가 그 한계를 인지하고 사용할 수 있도록 함

[필수 5] 작업 우선순위:
  - 정확성 > 속도
  - 빠른 산출 vs 정확한 산출 → **정확한 산출 선택**
  - 토큰/시간 한계로 일부만 가능하면 **사용자에게 먼저 알림** (단독 결정 금지)
```

### 2.2 사용자 의도 해석

| 사용자 표현 | AI 가 해야 할 일 |
|---|---|
| "모두 추출" | 가능한 **모든 추출 경로** 검토. 다중 패턴 + 간접 호출 + Cross-check |
| "정밀하게" | 자동화 결과 채택 금지. **각 항목 직접 검증** |
| "상세하게" | DMF0008/SCP0001 수준의 풍부한 내용. **빈 칸 최소화** |
| "전체" | 일부 SKIP 금지. 진짜 전체 처리 (또는 한계 명시 후 사용자 결정) |
| "원소스 기반" | 원본 .cs/.sql 직접 Read 의무. 메타/캐시/요약본 단독 사용 금지 |
| "각각의 화면" | 화면당 개별 Read + 개별 산출. 일괄 자동화 금지 |

## §3. 작업 시작 전 자기 점검 (모두 ✓ 필수)

```
☐ 사용자가 "모두/전체/정밀/상세" 표현을 썼는가?
   → 그렇다면 다중 패턴 + cross-check 의무

☐ 기존 분석 자료 (_phase1~4, _screens, _asis_mappings) 를 검토했는가?
   → 그렇지 않으면 작업 중단, 자료 확인 후 재시작

☐ 추출 패턴이 1개뿐인가?
   → 그렇다면 즉시 다중 패턴 + 변수 추적 + 헬퍼 분석 추가

☐ 자동화 결과를 단독으로 채택하려 하는가?
   → 즉시 cross-check 단계 추가

☐ 작업 시간이 길어질 것 같다고 단순화하려 하는가?
   → 사용자에게 먼저 안내, 단독 결정 금지

☐ 샘플 1건만 검증하고 전체 결론 내리려 하는가?
   → 최소 5~10건 또는 전 도메인 분포로 검증
```

**1건이라도 ✗ → 작업 중단, 보완 후 재시작**

## §4. 산출 직후 자동 검증

```bash
# 1. 추출 결과의 카운트가 기존 자료와 일치/유사한가?
#    - 예: 매트릭스 SP 카운트 vs 분석서 6_APIEndpoint 시트 SP 카운트
diff <(매트릭스 SP) <(분석서 SP) | head

# 2. 0건 또는 비정상적으로 적은 화면이 있는가?
SELECT 화면, COUNT(SP) FROM 매트릭스 GROUP BY 화면 HAVING COUNT(SP) = 0;
# → 0건 화면이 다수면 추출 누락 의심

# 3. 사용된 추출 패턴이 1개뿐인가?
grep -c "re.compile\|re.search\|re.findall" extractor.py
# → 1개면 단순화 의심, 다중 패턴으로 보강

# 4. 산출물에 "추출 한계" 가 명시되어 있는가?
grep -i "추출 한계\|limitation\|caveat" 산출물.md
```

**1건이라도 ✗ → 머지/제공 차단**

## §5. 사용자에게 알릴 의무

다음 경우 **반드시 사용자에게 먼저 안내**, 단독 결정 금지:

| 상황 | 안내 내용 |
|---|---|
| 작업 시간이 1세션을 초과할 것 같음 | 예상 소요 시간 + 단계적 진행 옵션 제시 |
| 자동화로 일부 패턴만 추출 가능 | 추출 한계 명시 + 보완 방법 제시 |
| 일부 화면에서 소스 부재 | 부재 화면 목록 + 처리 방법 (PASS/추론/대안 자료) 제시 |
| 기존 자료 vs 신규 산출물 차이 발견 | 차이 분석 + 원인 + 보완 방법 제시 |
| 작업이 사용자 의도와 다르게 진행됨 | 즉시 작업 중단 + 의도 재확인 |

## §6. 위반 시 절차

1. **즉시 인정**: 변명 없이 단순화 행위를 명시적으로 인정
2. **원인 분석**: 어떤 단순화를 했는지, 왜 했는지 정확히 보고
3. **영향 평가**: 산출물의 어느 부분이 잘못되었는지 명시
4. **보완 계획**: 정확한 재작업 방법 제시
5. **재작업**: 사용자 승인 후 정확한 방법으로 재작업

**절대 금지**:
- 단순화 사실 은폐
- "거의 다 맞다" 같은 표현으로 정당화
- 사용자가 검증할 때까지 알리지 않음
