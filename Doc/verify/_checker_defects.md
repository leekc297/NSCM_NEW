## 2. 재발 방지 3중 장치
1. **FAIL 발행 계약(judge)** — 직접 실측 FAIL 은 AS-IS/확정 규칙 근거를 판정에 제시해야 하고(없으면 `[근거 불충분]` ERROR), 대상 시트와 근거 시트가 같아야 한다(`[근거 축 불일치]`). 측정 실패 표식이 있으면 ERROR. 새 유형의 결함도 "근거 없는 FAIL" 이면 조치 필요에 오르지 못한다.
2. **조건 해시로 낡은 판정 폐기** — E2E 결과는 측정 시점 조건과 함께 저장되고, 조건이 바뀌면 재측정 전까지 FAIL 로 쓰지 않는다(T1).
3. **사용자 판정 = 회귀 오라클(`regress.py`)** — 모든 CheckList 판의 '사용자의견/사용자판정' 을 `Doc/verify/_user_verdicts.csv` 로 모아, 판정오류·대상아님 행의 검사기 **원판정**이 다시 FAIL 이거나 중복 행이 조치 필요에 별도로 남으면 위반으로 보고(`Doc/verify/_regress_report.md`). `run_verify` 끝에 자동 실행. 사용자 판정으로 행을 덮는 것(마스킹)과 별개로, 검사기 자체가 고쳐졌는지를 매 실행 확인한다.

## 3. 운영 규칙(KEEP H18)
- 검사기 결함을 고칠 때는 ① 결함 유형(T1~T12)을 적고 ② 같은 유형의 다른 화면·규칙에도 같은 구조인지 확인하고 ③ `regress.py` 전 화면 위반 0 을 확인한 뒤 끝낸다.
- 사용자 의견이 '판정오류/중복/대상아님' 이면 행 덮어쓰기로 끝내지 않고 원인 유형을 이 표에 추가한다.
- 새 검사기(규칙)는 FAIL 증거에 AS-IS 근거 참조(파일:행·메타 행·기준표·확정 룰)를 반드시 넣는다 — 계약 위반이면 조치 필요에 오르지 않는다.
