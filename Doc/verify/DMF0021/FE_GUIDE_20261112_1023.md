- 원인: SAVE 버튼은 시트 단위 권한(`mnuBtnAuthSheets`)으로 판정하는데 로컬 BE 가 이 값을 응답하지 않았다(공통 BE `b6cc747d6` 2026-11-02 미반영).
- 조치: 11-12 10:09 공통소스 다운로드(DB MODE)로 BE `src` 를 공통 최신(`61c936ba4`)으로 맞췄다. 환경 파일은 로컬 유지라서, 새 BE 가 요구하는 설정 3종이 로컬에 없다.

## 1. `nscm-be/build.gradle` 98~103행 — SSO 라이브러리 주석 해제
- 변경 전: 6줄이 `//    implementation files('lib/sso/…jar')` 로 주석.
- 변경 후: 6줄의 맨 앞 `//` 제거(공통 build.gradle 과 같은 6줄).
- 이유: 새로 받은 `SsoService.java` · `SsoController.java` 가 이 라이브러리를 쓴다. 주석이면 컴파일 오류 5건(10:09 실측).
- 로컬에서 SSO 서버에 접속하지는 않는다. 기동 시 `SsoService` 는 객체만 만들고, 로그인은 기존 `/user/login`(ID) 방식 그대로다(10:22 실측: 로그인 HTTP 200).

## 2. `nscm-be/src/main/resources/application.yml` 92~94행 `config.mybatis` — 4줄 추가
- 변경 전:
  ```yaml
    mybatis:
      logging-enabled: true
      logging-only-error: false
  ```
- 변경 후(공통 application.yml 값과 동일):
  ```yaml
    mybatis:
      logging-enabled: true
      logging-only-error: false
      queue-capacity: 10000
      batch-size: 500
      log-pool-size: 2
      flush-interval-ms: 1000
  ```
- 이유: `log-pool-size` 가 없으면 0 으로 읽혀 Oracle 연결 풀 생성이 실패한다(`maxPoolSize cannot be less than 1`). 그 결과 로그인이 401 로 떨어진다(10:16 실측).

## 3. `nscm-be/src/main/resources/config/config-local.yml` — `config.system-cd` 1줄 추가
- 변경 후: `config:` 아래에 `system-cd: NSCM` (공통 config-local.yml 과 같은 위치·값).
- 이유: 새 BE 가 메뉴 조회 `PR_GET_MENU_LIST_V2` 에 시스템 구분을 넘긴다. 값이 없을 때의 동작은 재지 않았다(임시 기동에서는 NSCM 을 넣어 로그인·메뉴 응답 정상).

1. `nscm-be` 에서 `gradlew.bat compileJava --offline` → 성공.
2. `gradlew.bat bootRun` → 로그에 `Started ScpApplication`.
3. 로그인 후 `GET /admin/menu/DMF0021/auth` 응답에 `mnuBtnAuthSheets` 가 있고 `Sales Plan` / `SAVE` 가 포함.
4. DMF0021 화면을 새로 열어 SAVE 버튼 표시 확인.
