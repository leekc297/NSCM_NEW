## 지금 개념

개선안이 고친 내용이 맞는지 확인하려고, 작성 AI 가 쓴 verify 글 전체를 반영 AI 가 실행하고 verified 값 하나를 내며, 그 값이 true 가 아니면 대상 파일을 전부 되돌린다.

- verify 는 글 한 덩어리로 저장하고 등록 때 검사하지 않음(`tools/VibeManager/orch-improve.js` add, 54행)
- 작성 규칙 VERIFY_RULE 은 작성 AI 에게 주는 문장임(46행). 어겨도 등록됨
- `verified !== true` 이면 대상 파일 복원 뒤 apply-failed(approve, 307행)
- 실패한 안은 같은 글로 남고, 승인하면 같은 글로 다시 실행함

## 대안 개념

### A. 검증을 항목으로 나누고 판정을 코드가 함

- 항목마다 시점을 나눔: 반영할 때 실행, 반영 뒤 확인, VMO 게이트 판정
- 합격은 반영할 때 실행한 항목 결과로 코드가 판정함. 실패 1건이면 종전처럼 되돌림
- 반영 뒤 확인 항목과 실행하지 못한 항목은 확인 목록으로 넘기고 CHANGELOG 미확인 줄에 남김
- 어긋난 사례: 잴 수 없는 항목 9건은 확인 목록으로 가고 반영은 유지됨. 기대값 9건 중 'run_all 전체 통과'는 게이트 판정으로 감
- 새로 할 것: 분류 코드, 판정 코드, 반영 지시문과 결과 형식. 버리는 것: verified 값 하나로 하던 판정
- 이미 등록된 안에도 적용됨(반영 직전에 분류)

### B. 등록 때 검증 글을 검사해 거절함

- 반영 뒤 확인 문구, 절대값 문구가 있으면 등록하지 않고 작성 AI 에게 돌려보냄
- 어긋난 사례: 새로 쓰는 안에서는 걸러짐. 이미 등록된 대기 12건과 실패 1건에는 적용 안 됨
- 새로 할 것: 거절 뒤 다시 쓰는 호출. 거절마다 AI 호출이 1회 늘어남
- 반영 뒤에만 확인할 수 있는 항목(CheckList 실행 뒤 대조)을 적을 곳이 없어짐

### C. 반영 AI 가 실행하지 못한 항목을 스스로 빼고 true 를 냄

- 지시문만 고침. 판정 근거가 AI 판단 하나라 실패한 항목을 실행 못 함으로 내도 코드가 알 수 없음

## 권장안과 이유

A. 이미 등록된 안에도 적용되고, 실패 항목은 종전대로 되돌리며, 반영 뒤에만 확인할 수 있는 항목이 기록으로 남음. AI 호출이 늘지 않음.

## 전환(바뀌는 것 · 버리는 것 · 단계 · 확인 · 위험 · 되돌리기)

- 1단계(2026-11-23 14:21 설치 폴더 복사): `orch-verify.js` 신규(분류, 판정), `orch-improve.js` approve 연결, `test/t_orch_verify.js` 신규
- 확인: t_orch_verify.js 25건 통과. 실제 개선안 122건 verify 를 분류해 반영 뒤 확인 17항목 전부 원문 대조. run_all 66/68 파일(실패 2개 파일은 변경 전부터 실패)
- 2단계(미착수): 작성 AI 가 verify 명령을 등록 전에 1회 실행해 반영 전 값을 채움. 대상 파일을 참조하는 시험 파일을 코드로 찾아 대상에 넣음
- 3단계(미착수): 작성 뒤 대상 파일이 바뀐 안은 승인 전에 다시 쓰게 함
- 4단계(미착수): 같은 사유로 2회 실패한 안은 승인을 막음. 반영 실패 묶음 기준을 실패 사유로 바꿈
- 5단계(미착수): 확인 목록(postChecks)을 감시기가 해당 실행 뒤 닫음. 지금은 기록만 함
- 위험: 실행할 수 있는 항목을 반영 AI 가 실행 못 함으로 내면 확인 없이 반영됨. 게이트 없는 안은 실행 통과 0건이면 불합격으로 막음. 게이트 있는 안은 게이트가 판정함
- 위험: 분류 문구에 없는 표현의 반영 뒤 확인 항목은 반영할 때 실행으로 남음. 반영 AI 가 실행 못 함으로 내면 확인 목록으로 감
- 되돌리기: `tools/VibeManager/orch-verify.js` 와 설치 폴더의 같은 파일을 지우면 종전 판정(verified 값)으로 돌아감

## 반증

- A 가 틀렸다면 전환 뒤에도 '검증 실패' 반영 실패가 같은 비율로 나와야 함. 확인: 전환 뒤 7일 이력에서 사유별 건수
- 확인 목록으로 넘긴 항목에서 결함이 반복해 나오면 판정이 느슨한 것임. 확인: postChecks 가 있는 반영 완료 안의 되돌리기, 재발 건수
