## 지금 개념

VM 코드(tools/VibeManager/*.js)의 문자열 리터럴 전부를 '고정 문구'로 보고, 무거운 점검 주기(VM 파일 변경 뒤, 24시간마다)에 doc_style.py 로 위반을 센다(orch-selfcheck.js:219-229). 위반이 있는 파일마다 주의 항목 'S11|<파일>'을 올리고, 자가진단 AI 가 파일을 몇 개씩 묶어 정리 개선안을 만든다(orch-selfcheck.js:367). 반영 게이트는 구문, test/run_all.js, 정의 정합 3가지이고 doc_style.py 는 들어 있지 않다(vm-orchestra.md:94, CHANGELOG.md:4 확인 줄 형식). 건수형이라 S8 재발 판정에서 빠진다(orch-selfcheck.js:193-194). Overall Review 는 판정 기준 없이 AI 가 판단하고(orch-vision.js:72-78), 실제 판정 근거는 '위반이 남아 있음'이다(vision/20261121_120359.json:69). 정리하면 '문장 규칙을 지키게 하려고, VM 코드의 문자열 전부를, 다 쓴 뒤 나중에 센 위반 건수 0을 기준으로' 관리한다.

## 대안 개념

### A 대상 다시 정하기

고정 문구를 셋으로 나눈다. (1) 사람이 읽는 문장(알림, 화면 설명, 보고, Claude 지시문): 문장 규칙 대상. (2) 코드와 시험이 읽는 표지(FAIL_RE 의 ✖, 진행 표지 ▶, 상태 기호): 문장이 아니므로 대상에서 빼고, 이름 붙인 상수로 한곳에 모은다. (3) 사용자가 정한 메뉴, 환경설정 이름 인용('🔁 VMO 보완 뒤 재수행' 등): 원문 인용이라 그대로 둔다. 셈은 (1)만 한다.
- 목적 충족: 규칙 4는 '문장 안' 기호를 막고, 끝 문단은 라벨 인용을 고치지 말라고 함. 대상이 이 문장과 맞아진다.
- 어긋난 사례: 표지를 고치다 시험이 깨지는 실패가 없어진다. 기호 109건 중 (2), (3)으로 빠지는 수는 미측정이다.
- 새로 할 일: doc_style.py 에 JS 분류 규칙 추가(표지 상수 목록, 메뉴 이름 목록은 quick.json, steps.json 에서 읽음). 버릴 것: KNOWN_OK 하드코딩 제외 9건.
- 한계: 쓰는 시점에 막지 않으므로 새 위반 유입(+3, +1)은 그대로다.

### B 쓰는 시점에 막기

문장 규칙은 다 쓴 뒤에 세지 않고, 문구를 쓸 때 지킨다. VMO 반영 게이트(구문, 시험, 정의 정합)에 '바뀐 파일의 S11 위반 수가 반영 전보다 늘지 않음'을 더한다. Claude 세션이 tools/VibeManager 를 고칠 때도 같은 검사를 쓴 직후 실행한다(post-write). 기존 위반은 파일별 정리를 날마다 나눠 하지 않고, 계획 1건으로 한 번에 정리한다. Overall Review 판정 기준은 '새로 생긴 위반 0건, 대상 문장 잔량 0건'이다.
- 목적 충족: 메모리 원문 '생성기에 문장을 새로 넣거나 고치면 … 위반 0 확인'과 같다.
- 어긋난 사례: +3, +1 유입이 게이트에서 막힌다. 16회 반복 정리가 1회로 줄어든다.
- 새로 할 일: orch-improve.js, orch-selfcheck.js 게이트에 S11 증감 비교 추가. 버릴 것: S11 파일별 주의 항목을 AI 정리 개선안으로 매번 돌리는 흐름.
- 한계: A 의 분류가 없으면 표지, 메뉴 이름까지 게이트가 막아 반영 실패가 늘어난다.

### C 지금 개념 유지, 정리 속도만 올림

주기와 묶음 크기를 늘려 남은 119건을 빨리 줄인다.
- 어긋난 사례: 유입은 그대로고, 표지를 고치다 시험이 깨지는 실패도 그대로다. 버리는 것은 없다.

## 권장안과 이유

B 를 권장하고, A 의 분류를 B 전환의 첫 단계로 넣는다. 근거는 두 가지다. 첫째, 판정이 0건에 닿지 못한 직접 원인은 쓰는 시점 검사가 없는 데 있다. 정리 사이 유입 +3, +1 이 측정됐고, 같은 모듈을 3번 다시 정리했다. 둘째, B 만 넣으면 기호 109건 안의 코드 표지와 메뉴 이름 인용이 게이트를 막는다(이 둘을 고치려다 반영 실패한 기록 있음). 그래서 A 의 분류가 먼저 있어야 한다. C 는 두 원인 중 어느 것도 없애지 않는다.

## 반증

- 단계 2 게이트를 켠 뒤에도 정리 사이 위반 증가(+n)가 측정되면 '쓰는 시점에 막으면 유입이 멈춘다'는 가정이 틀린 것이다. 이 경우 게이트를 거치지 않는 경로(사용자 세션 직접 수정 등)를 찾는다.
- 단계 1 분류 결과 기호 109건 중 표지, 이름 인용이 0~소수이면 '표지가 섞여 0건이 안 된다'는 근거가 약하다. 그때는 단계 3 일괄 정리만으로 판정을 바꿀 수 있는지 다시 본다.
- 단계 3 뒤 7일 안에 같은 목적이 다시 어긋남이면 이 재정립은 틀린 것이다.
