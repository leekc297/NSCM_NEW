## 대안 개념
### A 원인 서명 묶음
- 개념: 구조 개선안이 반영될 때 재발 서명을 같이 남김. 서명 = 대상 함수 또는 줄 범위, 사건 규칙(R14, R11, R5), 이벤트 조건(user.stop 에 runId 없음, 실행 중). L4는 효력 뒤 그 서명이 다시 걸린 건수로만 올림
- 목적 충족: 구조를 고쳤는데 같은 원인이 다시 났는지를 측정값으로 봄. 플랜 2.2의 '같은 묶음 조건이 다시 참'을 원인 단위로 지킴
- 어긋난 사례가 어떻게 되나: 이번 묶음은 서명 재발(R14 0, R11 0, endRun 대상 함수 결함 절 0)이 없어 L4로 올라오지 않음. 대신 runId 없는 user.stop 23줄이 실행 중 기록이면 서명 재발로 잡힘
- 새로 할 일: 개선안 JSON 에 recurSig 필드 추가, vmo-diagnosis-ladder L3 결과 형식에 서명 칸 추가, 절 종류에 '같은 방식 반영(propagate)' 추가, 변경 줄과 원인 줄의 파일만 '고친 파일'로 셈
- 버리는 것: 파일 전체 결함 건수로 L4 올림(orch-ladder.js:140 editsAfter)
### B 목적 근거 전용
