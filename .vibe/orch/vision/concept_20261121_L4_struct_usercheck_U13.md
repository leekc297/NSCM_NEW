## 대안 개념
### A 재발 = 효력 뒤 새로 생긴 증상 사건
- 개념: 사용자 지적 재발은 원문이 말한 증상(U13 = 창 다시 로드로 중단된 실행이 재개되지 않음)이 반영 효력 뒤에 일어난 사건으로 확인될 때만 센다. 사건 시각은 그 일이 일어난 시각(U13 = 중단 사건 ms)이다. 감지기가 본 시각은 쓰지 않는다.
- 감지기 항목을 둘로 나눈다. 증상(fail, 사건 ms 필수)과 판정 근거 부족(warn, 데이터 상태). 사다리 L3, L4 는 증상만 센다. 근거 부족 warn 은 L1(기록 정리 대상)으로 보낸다.
- 어긋난 사례: 'S13,U13,old' 는 warn 이라 사다리에서 빠진다. L4 묶음 후보 0건. 효력 뒤 실제 중단이 30분 넘게 재실행 없이 남으면 fail(ms = 중단 시각)로 종전대로 L3 에 오른다.
- 새로 할 일: 감지기 결과에 kind(symptom, basis) 필드. 사다리에서 ms 없는 증상 항목은 재발로 세지 않고 '판정 근거 없음' 점검 항목으로 올림. itemMs 의 대체 순서(state, 점검 시각, 지금) 폐지.
- 버리는 것: '지금 걸린 항목이 있으면 재발' 판정. 감지기 첫 기록 시각을 사건 시각으로 쓰는 대체 규칙.

### B 재발 = 지적별 목적 재현 시험 실패
- 개념: 지적마다 원문 목적을 재현하는 시험(U13 = 창 다시 로드 기록 뒤 VMW 표기, 재개 단추 활성, 끊긴 단계부터 재개 사건 줄)을 실제 기록으로 돌리고, 효력 뒤 시험이 실패할 때 재발로 센다.
- 어긋난 사례: 옛 작업 3건은 시험 대상 창 로드(효력 뒤)와 무관하므로 제외된다.
- 새로 할 일: 지적 23건마다 목적 시험 정의, 기록 재생기. 감지기와 시험을 둘 다 관리.
- 버리는 것: 감지기 항목을 재발 근거로 쓰는 것.
- 부담: 지적마다 시험을 새로 써야 하고, U13 처럼 사용자 화면 동작(단추 활성)은 기록만으로 확인할 수 없는 부분이 남는다(미확인 항목 증가).

### C 개념 유지, 옛 기록 정리
- 옛 작업 3건을 재개 불가로 표시하거나 지워 warn 을 없앤다.
- 다음에 사건 기록 이전 데이터나 다른 근거 부족 warn 이 생기면 같은 순환이 다시 난다. 개념은 그대로라 재발 방지가 안 된다. 사용자 작업 파일(job.json) 변경이라 승인 대상이다.

## 권장안과 이유
A 를 권장한다.
- 사용자 원문 목적은 재개 못 하는 작업이 다시 생기지 않는 것이다. 재발 판정도 그 증상 사건으로 해야 목적과 같은 단위가 된다.
- 이번 L4 는 증상 0건에서 올라왔다. A 에서는 올라오지 않고, 실제 증상은 종전대로 잡는다. 할 일을 빼지 않는다(warn 은 L1 로 옮겨 계속 보임).
- B 는 목적에 더 가깝지만 지적 23건 전부에 시험을 새로 써야 하고 화면 동작은 미확인으로 남는다. A 를 먼저 하고, A 뒤에도 증상 판정이 어긋나는 지적만 B 로 넘긴다.
- 승인 대상을 줄인다. 근거 부족 warn 이 L3, L4 개선안과 사용자 승인으로 이어지지 않는다.
