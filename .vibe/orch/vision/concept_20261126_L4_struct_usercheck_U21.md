U21 감지기 applyFailRepeat(orch-usercheck.js:471~502)는 원인과 무관하게 history 의 '반영 실패' 기록을 센다. 24시간 2건 이상이면 fail 로 판정한다.

## 대안 개념

### B 반영 전 준비 확인을 둠(권장)
반영은 준비가 확인된 안만 시작한다. 반영 전 준비 확인에서 4가지를 본다.
1. 대상 파일이 있음.
2. 근거와 보류 사유에 적힌 고칠 파일이 targets 안에 있음.
3. 최근 N분 안에 다른 세션이 대상 파일을 고치지 않음.
4. 보류 사유가 사실 근거(대상 밖, 일치 0행 같은 측정값)일 때 해소 기록이 있음.

확인을 통과하지 못한 안은 '반영 실패'가 아니라 '대상 재진단'으로 보낸다. VMO 가 대상을 고쳐 새 안으로 다시 올린다. autoApplyAll 은 '사람 승인 없음'으로 읽는다. 사실 근거로 막힌 보류는 사람 대신 VMO 재진단이 푼다. 반영 실패는 준비 확인을 통과한 뒤 게이트나 실행에서 어긋난 경우만 센다.
- 목적 충족: 사용자 승인 없이 진행한다는 지시를 지키면서 원인을 찾아 보완하는 단계를 VMO 가 스스로 닫는다(자가 보완 목적의 감지 → 원인 → 해결 → 확인).
- 18:17 사례: 17:26 보류 사유의 facts_lockrules.py 가 targets 에 없어 준비 확인에서 막힘. 대상 재진단으로 감. 반영 실패 0건.
- 012049_SELF_5 사례: 대상 없음으로 막힘. 014508_SELF_3 사례: 동시 편집으로 다음 차례로 미룸.
- 새로 할 것: 준비 확인 함수, 대상 재진단 경로, 감지기 셈 대상 변경.
- 버리는 것: holdOk 가 사실 근거 보류를 넘어가는 동작.

### C 반영 실패를 결과 단위로 셈
반영 실패 메시지 건수 대신 개선안 하나가 최종으로 풀렸는지를 본다. 실패 뒤 VMO 가 재진단해 다시 반영하고 풀리면 실패로 남기지 않는다. 미해결로 24시간 남은 안만 fail 로 본다.
- 목적 충족: 사용자가 보는 반영 실패 메시지는 줄지 않음. 원문 "반영 실패 메세지가 발생하는데"와 어긋남.
- 18:17 사례: 미해결 기간만 봄. 반영을 시작하면 안 되는 안을 막지 않음.
