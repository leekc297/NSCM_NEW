## 1. 원인 — MERGE 조인키에서 `MEASURE` 가 빠졌습니다

`PKG_DMF0021` L840 의 MERGE 입니다.

```sql
840|    MERGE INTO GT_DMF0021_RAW_DATA A
841|    USING ( SELECT DIVISION_ID, PROJECT_CODE, SCM_SITE_ID, ITEM_ID, DOM_EXP, FCST_TYPE, INCOTERMS, PLANT_SITE_ID, YYYYMMDD
842|                 , ATTRIBUTE1, REMARK_TEXT
843|                 , '-' AS CELL_PROD_SITE_ID
844|              FROM DM_PLN_SALES_ETC_PLAN
845|             WHERE DIVISION_ID = '40'
846|               AND FCST_TYPE   = 'ETC'
847|               AND YYYYMMDD >= p_now_yyyymmdd AND YYYYMMDD <= p_to_yyyymmdd
848|               AND QTY <> 0 ) B          ← ⛔ DISTINCT 도 GROUP BY 도 없음
849|       ON ( ... 10개 컬럼 조인 ... )
860|     WHEN MATCHED THEN UPDATE SET A.ATTRIBUTE1 = B.ATTRIBUTE1;
```

### `DM_PLN_SALES_ETC_PLAN` PK 는 **11 컬럼**입니다

| # | 컬럼 | MERGE 조인키 사용 |
|---:|---|---|
| 1 | DIVISION_ID | ✅ |
| 2 | PROJECT_CODE | ✅ |
| 3 | SCM_SITE_ID | ✅ |
| 4 | ITEM_ID | ✅ |
| 5 | REMARK_TEXT | ✅ (L858) |
| 6 | DOM_EXP | ✅ |
| 7 | FCST_TYPE | ✅ |
| 8 | INCOTERMS | ✅ |
| **9** | **MEASURE** | **⛔ 미사용** |
| 10 | PLANT_SITE_ID | ✅ |
| 11 | YYYYMMDD | ✅ |

**`MEASURE` 하나가 빠져 있습니다.** 그래서 같은 키에 MEASURE 만 다른 행이 여러 개 있으면
`USING` 이 대상 1행에 **여러 행을 매칭** → `ORA-30926`.

```sql
                 PLANT_SITE_ID,YYYYMMDD,NVL(REMARK_TEXT,'#')

```

**사내 결과**: 중복 그룹 **1** / 행 **3** / 키당 최대 **3** / **ATTRIBUTE1 이 다른 그룹 0**

실제 중복 사례:

| PROJECT_CODE | ITEM_ID | YYYYMMDD | 행수 | MEASURE 조합 | ATTRIBUTE1 종류 |
|---|---|---|---:|---|---:|
| NT | ETC_P | 20260630 | 3 | `SalesAmt_KRW, SalesAmt_LOC, SalesAmt_USD` | **1** |

→ **통화별 금액 measure 3종**이 같은 키에 존재합니다. 그리고 그 3행의 **`ATTRIBUTE1`(dept_id)은 동일**합니다.

### 왜 사내는 정상이고 클라우드만 실패하는가
사내의 유일한 중복 그룹이 `YYYYMMDD=20260630` 이라 `AND YYYYMMDD >= p_now_yyyymmdd`(오늘 이후) 조건에서 **제외**됩니다. 클라우드는 조회 기간 안에 해당 데이터가 있는 것으로 보입니다.
→ **사내도 동일한 잠재 결함**을 갖고 있습니다. 데이터가 조회 기간에 들어오면 똑같이 터집니다.

## 3. 클라우드 확인용 진단 SQL (READ-ONLY)

```sql
-- 실패한 조회의 p_now_yyyymmdd ~ p_to_yyyymmdd 구간으로 바꿔 실행
SELECT PROJECT_CODE, SCM_SITE_ID, ITEM_ID, PLANT_SITE_ID, YYYYMMDD,
       NVL(REMARK_TEXT,'#') RT, COUNT(*) CNT,
       LISTAGG(MEASURE,',') WITHIN GROUP (ORDER BY MEASURE) MEASURES,
       COUNT(DISTINCT NVL(ATTRIBUTE1,'~')) ATTR1_종류,
       LISTAGG(DISTINCT NVL(ATTRIBUTE1,'~'),'|') WITHIN GROUP (ORDER BY 1) ATTR1_값
  FROM DM_PLN_SALES_ETC_PLAN
 WHERE DIVISION_ID='40' AND FCST_TYPE='ETC' AND QTY<>0
   AND YYYYMMDD >= TO_CHAR(SYSDATE,'YYYYMMDD')      -- ← p_now_yyyymmdd
 GROUP BY PROJECT_CODE, SCM_SITE_ID, ITEM_ID, DOM_EXP, FCST_TYPE, INCOTERMS,
          PLANT_SITE_ID, YYYYMMDD, NVL(REMARK_TEXT,'#')
HAVING COUNT(*) > 1
 ORDER BY CNT DESC;
```

⭐ **`ATTR1_종류` 컬럼이 판단의 핵심입니다.**
- 전부 **1** 이면 → 아래 §4 패치가 **의미 변화 없이 안전**합니다.
- **2 이상**이 하나라도 있으면 → 어느 값을 남길지 **업무 판단이 필요**합니다(패치 보류).

## 4. 패치안 (미적용) — `USING` 을 조인키 단위로 집약

`ATTRIBUTE1` 이 그룹 내 동일하다는 전제이므로 `MAX()` 는 임의 선택이 아니라 **동일값 확정 선택**입니다.

### Before (L841~848)
```sql
    USING ( SELECT DIVISION_ID, PROJECT_CODE, SCM_SITE_ID, ITEM_ID, DOM_EXP, FCST_TYPE, INCOTERMS, PLANT_SITE_ID, YYYYMMDD
                 , ATTRIBUTE1, REMARK_TEXT --[PJ2024-50611] 기타매출, Catch Up 테이블 분리 : 필드추가
                 , '-' AS CELL_PROD_SITE_ID --[PJ2025-50017] CELL_PROD_SITE_ID 추가
              FROM DM_PLN_SALES_ETC_PLAN --[PJ2024-50611] 기타매출, Catch Up 테이블 분리 : 테이블 변경
             WHERE DIVISION_ID = '40'
               AND FCST_TYPE   = 'ETC'
               AND YYYYMMDD >= p_now_yyyymmdd AND YYYYMMDD <= p_to_yyyymmdd
               AND QTY <> 0 ) B
```

### After
```sql
    USING ( SELECT DIVISION_ID, PROJECT_CODE, SCM_SITE_ID, ITEM_ID, DOM_EXP, FCST_TYPE, INCOTERMS, PLANT_SITE_ID, YYYYMMDD
                 , MAX(ATTRIBUTE1) AS ATTRIBUTE1, REMARK_TEXT --[PJ2024-50611] 기타매출, Catch Up 테이블 분리 : 필드추가
                 , '-' AS CELL_PROD_SITE_ID --[PJ2025-50017] CELL_PROD_SITE_ID 추가
              FROM DM_PLN_SALES_ETC_PLAN --[PJ2024-50611] 기타매출, Catch Up 테이블 분리 : 테이블 변경
             WHERE DIVISION_ID = '40'
               AND FCST_TYPE   = 'ETC'
               AND YYYYMMDD >= p_now_yyyymmdd AND YYYYMMDD <= p_to_yyyymmdd
               AND QTY <> 0
             --[2026-07-31] ORA-30926 fix : PK 11컬럼 중 MEASURE 가 조인키에서 빠져
             --             같은 키에 통화별 measure 다건(SalesAmt_KRW/LOC/USD)이 매칭됨.
             --             조인키 단위로 집약해 대상 1행당 소스 1행을 보장한다.
             GROUP BY DIVISION_ID, PROJECT_CODE, SCM_SITE_ID, ITEM_ID, DOM_EXP, FCST_TYPE
                    , INCOTERMS, PLANT_SITE_ID, YYYYMMDD, REMARK_TEXT ) B
```

변경은 **2줄**입니다 — `ATTRIBUTE1` → `MAX(ATTRIBUTE1) AS ATTRIBUTE1`, 그리고 `GROUP BY` 추가.
`ON` 절(L849~859)과 `WHEN MATCHED`(L860)는 **무수정**입니다.

### 대안 (참고)
| 안 | 내용 | 판단 |
|---|---|---|
| **A. GROUP BY 집약 (위)** | 조인키 단위 1행 보장 | ✅ 권장 — 최소 변경, 의미 보존 |
| B. `ON` 절에 `MEASURE` 추가 | `A.MEASURE = B.MEASURE` | ⛔ `GT_DMF0021_RAW_DATA` 의 MEASURE 의미가 원천과 같은지 확인 필요. 매칭 대상이 달라져 결과가 바뀔 수 있음 |
| C. `USING` 에 `DISTINCT` | `SELECT DISTINCT ...` | ⛔ `ATTRIBUTE1` 이 다른 행이 있으면 여전히 중복 → 해결 못 함 |
