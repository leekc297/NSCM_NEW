## 3. ⚠ 핵심 설계 — 날짜 동등비교가 아니라 **캘린더 주차 매핑**

입력행(`GT_PRDM1_T_MAIN`)은 **일 단위 행이 실재**하고(FE 가 주 단가를 월=값·화~일=0 으로 전송 — `[E20260822-LOCWEEKSUM]` 참조),
판가 원장은 주 시작일로 적재된다. 사내 실측:

- `DM_PLN_CFM_SELLING_PRICE`(LOC) — 주 시작일 **19,994 / 20,000**
- `DM_PLN_CFM_MKT_DEMAND_PLAN`(MKT_FCST) — 주 시작일 **12,527 / 15,664** (= 일 단위 행 3,137)

따라서 `A.YYYYMMDD = P.YYYYMMDD` 로 비교하면 안 되고, `SCM_SYS_CALENDAR_M` 으로 주차(`BASIS_START_DATE`)를 맞춰야 한다.
삭제 가드는 원래부터 `ISO_YYYYWW` 로 주차를 맞추고 있었으므로 윈도우만 제거하면 된다.

## 5. 영향 고지

- **완화**: 52주 전 구간 판가 완비를 요구하지 않으므로, 판가가 일부 주차만 등록된 키도 **그 주차에는 메저 입력 가능**. 종전 대비 저장 성공 범위가 넓어진다.
- **신규 제약**: 52주를 넘는 주차에 메저를 입력하는 경우, 종전에는 52주 구간만 보던 판정이 이제 **그 주차의 판가**를 요구한다(`[E20260908-GETRANGE]` 로 52주 이후 저장이 열려 있는 경로).
- **삭제 가드 완화**: 종전에는 키만 맞으면 52주 안 아무 주차에 FCST 가 있어도 판가 삭제가 막혔다. 이제 **같은 주차**에 있을 때만 막힌다.
- ⚠ **미해결(기존 조건 승계)**: 판가 원장에 주 시작일이 아닌 행이 **6건/20,000** 존재한다. 수집 시 정규화하지 않으므로 그 행은 판정에서 누락된다(AS-IS 도 동일). 정규화가 필요하면 별도 지시 필요.
