## Step 2. 전수 Read (요약 대체 금지)

- UI분석서는 **10시트 전량 덤프** 후 읽는다 (openpyxl → 텍스트).
- TO-BE 구현은 **Page / constants / store / Form / Grid / utils / modals 전부**. 부분 grep 로 대체 금지.
- SQL 아티팩트에서 **MSG_ID 별 KO 실문구**를 뽑는다 — 기대 메시지의 단일 근거.
  `grep -h -o "MSG00[0-9]\{3\}'[^)]\{0,180\}" _artifacts/_apply_corporate/{ID}_*.sql`
- SAVE SP 의 **결과 커서 컬럼명**(RESULT_CODE/CODE 등)을 확인해 FE 판독 키와 대조 → 불일치 시 격차 TC 로 남긴다.

## Step 3. 기대값 규칙

1. **대상은 TO-BE 화면.** 메시지는 사내 등록 SQL 실문구 그대로, `비고` 에 AS-IS 원 ID 병기 (예: `AS-IS MSG00002 → TO-BE MSG00429 재매핑`).
2. 실데이터 의존 항목(콤보 실목록, 계정별 권한 조합)은 값 대신 **규칙**으로 서술하고 한계를 밝힌다.
3. **미구현·미사용·격차는 반드시 TC 로 남긴다.** 항목명 앞에 `⚠`, 확인 사항에 현행 동작을, 비고에 근거와 결정 이력을 적는다. 숨기지 않는다.

## Step 4. 시트 구성 + 영역 설계

### 4-1. ⭐ Division 케이스는 시트로 분리 (필수)

한 시트에 전 Division 을 섞지 않는다. **테스터가 사업부 단위로 세션을 도는 현실**에 맞춰 나눈다.

| 시트 | 내용 | TC_ID |
|---|---|---|
| `TestCases` | **Division 무관 공통** — 진입/조회조건 공통/조회검증/그리드표시·개인화/공통 팝업/기타·회귀 | `TC-{ID}-{영역코드}{nnn}` |
| `Div{코드}` (예 `Div40` `Div81` `Div82`) | **해당 사업부에서만 성립하는 케이스** — 전용 조회조건·컬럼·키 / 편집 가부 / 권한·시간창 / 편집·배분·저장 전 흐름 / 전용 팝업 | `TC-{ID}-D{코드}-{nnn}` |

배치 규칙:
1. **편집 가능 Division 수로 갈린다.**
   - **1개뿐**이면 편집·신규행·배분·저장 영역 **전체**를 그 Division 시트에 둔다 (예 DMF0003 = 82). 공통 시트에 남기지 않는다.
   - **복수**면(예 DMF0082 = 40·81 계열) 공통 편집 흐름은 `TestCases` 에 두고 사전 준비에 "편집 가능 Division(…)" 을 명시한다. **Division 별로 기대값이 갈리는 것만**(키 컬럼·편집 Measure 화이트리스트·원장 테이블·전용 검증·전용 잠금) Division 시트로 뺀다.
2. 조회 전용 Division 은 **"편집 불가 확인"** 케이스를 반드시 포함한다(셀 편집 + 버튼 미표시).
3. 같은 항목을 여러 시트에 중복 기재하지 않는다. 판정이 Division 별로 다르면 각 시트에 **그 Division 의 기대값**으로 쓴다.
4. Division 축이 없는 화면(단일 사업부 고정 등)은 시트 분리 없이 `TestCases` 1장 + 사유를 개요 비고에 명기.
5. 사업부 코드 계열(81 / 81_HD·HG·HM·ST·UC 등)은 한 시트로 묶고 하위 코드 차이는 케이스로 구분.

### 4-2. 영역 코드 (12 표준 + 화면 특성 가감)

| 코드 | 영역 | 필수 포함 | 배치 |
|---|---|---|---|
| A | 화면진입 | 메뉴 경로 / 조회조건 기본값 / 버튼 구성(권한별) / 커스텀 버튼 / 코너 헤더 | 공통 |
| B | 조회조건·연동 | 콤보 cascade / Bucket·체크박스 / 팝업 필드 | 공통 |
| C | 조회검증·실행 | 필수·기간 검증 전건 / 버킷별 조회 / 0건 / 색·포맷·강조 | 공통 |
| D | 그리드표시·개인화 | 드릴다운 / Column·Measure 설정 / Sort·Filter / Excel / 머지·헤더높이 | 공통 |
| E | 편집권한·잠금 | 권한 게이트 / 행 EDIT_FLAG / 실적구간 / 버킷 정합 / 특수 잠금(M+4·RMA 등) | **Division 시트** |
| F | 신규행·삭제 | Insert 게이트·시드·cascade / 중복 실시간 검사 / Delete 분기 | **Division 시트** |
| G | 수량 배분·재계산 | 일↔주↔월 전 분기 / 기본요일 / 잔량 / 단가(LOC) 특수 규칙 | **Division 시트** |
| H | 저장 | 화면 검증 전건 + 확인·성공 + **SP 검증 문구 전건** + 실패 표출 | **Division 시트** |
| I | 팝업/부가기능 | 화면 전용 팝업(일괄입력·PR·환율 등) 검증·저장 전건 | 공통 / 전용이면 Division 시트 |
| J | 비교·결과 팝업 | 트리거 조건 / 미충족 시 무동작 / 표시 항목 | 트리거 Division 시트 |
| K | 전용 조건·컬럼 | 사업부 전용 조회조건·키 컬럼·반응형 컬럼·원장 | **Division 시트** |
| L | 기타·회귀 | 멀티탭 격리 / 조회조건 저장 / 대량 조회 / 미이관 기능 정직 표기 | 공통 |

화면에 없는 영역은 삭제하지 말고 **"해당 축 없음"** TC 1건으로 남긴다.

## Step 5. xlsx 생성 (openpyxl, 스크립트는 scratchpad)

포맷은 `Doc/DMF0004_SalesSite_TestCases.xlsx` 승계 — 임의 변경 금지.

- 시트 = `TestCases` + `Div{코드}` N장 (§4-1). **전 시트 동일 헤더 10열**:
  `No | TC_ID | 영역 | 테스트 항목 | 사전 준비 | 화면 조작 절차 | 입력값 | 화면에서 확인할 사항 | 표시되는 메시지 | 비고`
- TC_ID = 공통 `TC-{화면ID}-{영역코드}{3자리}` / Division 시트 `TC-{화면ID}-D{코드}-{3자리}`
- `No` 는 **시트별 1번부터** 부여. Division 시트의 `사전 준비` 첫 줄에 **해당 Division 조회 상태를 명시**한다.
- 서식: 헤더 `F2E1D9` 채움 + 11pt 굵게 가운데 / 본문 11pt 맑은 고딕 wrap·상단정렬 / 얇은 테두리 `BFBFBF` / `freeze_panes='A2'` / gridline off / autofilter 전체
- 열폭: `5.625 / 20.625 / 16.625 / 38.625 / 30.625 / 55.625 / 22.625 / 60.625 / 32.625 / 35.625`
- 서술: 절차는 `1) … 2) …`, 확인 사항은 `• ` 불릿, 메시지는 `MSGxxxxx : 문구`, 없으면 `없음`

산출 경로: `Doc/단위테스트/{화면ID}_{화면명}_TestCases.xlsx`
(파일이 열려 있어 저장 실패하면 `_v2` 로 저장하지 말고 사용자에게 알린다.)

## Step 6. 검증 + 카운트 대사 (보고 의무)

재오픈 assert (**전 시트 각각**):
- 시트 = `TestCases` + Division 시트 N / 10열 / **빈 셀 0** / freeze `A2` / autofilter 존재
- TC_ID 중복 0 (**시트 간 통합 기준**) / `No` 시트별 1부터 연속

커버리지 대사 (스크립트로 계산해 수치로 보고):
- **화면 검증 MSG 전건** ↔ TC 등장 여부 (**전 시트 합산**, `미커버: 없음` 이어야 통과)
- **SP 검증 문구 전건** ↔ TC 등장 여부
- 이벤트·버튼·조회조건 인벤토리 수 ↔ 해당 영역 TC 수
- **Division 축 대사**: 분석서 Division 매트릭스 행(전용 조건·컬럼·편집 가부) ↔ 각 Division 시트 TC 수

## Step 7. 보고 양식

```
{화면ID} TestCases — 총 N건 / 시트 M장 (TestCases + Div…)
시트별·영역별 표 (건수)
근거: 문서 원천 / TO-BE 구현 / 적용 SQL (각 링크)
카운트 대사: MSG a/a · SP 검증 b/b · 빈 셀 0 · ID 중복 0 · Division 축 c/c
발견한 격차·결함 (있으면 번호 매겨 TC_ID 와 함께)
한계: 실측 불가 항목 명시
```

## 금지 사항

- ❌ 원천 일부만 읽고 TC 도출 (요약본·grep 만으로 대체)
- ❌ 영역 축소 / "대표 케이스만" 샘플링
- ❌ **Division 케이스를 한 시트에 섞어 기재** (§4-1 위반) / 같은 케이스를 여러 Division 시트에 중복 복사
- ❌ 메시지 문구를 fallback 문자열·기억으로 기입 (등록 SQL 실측만)
- ❌ 격차·미사용 기능 은폐
- ❌ TestCases 를 UI분석서·화면설계서 안에 시트로 추가 (hook #105 §0 위반)
