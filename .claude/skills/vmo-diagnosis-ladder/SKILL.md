# VMO 진단 사다리

VMO 가 고치는 문제는 크기가 다르다. 문구 한 줄과, 같은 결함이 고쳐도 되풀이되는 설계 문제와, 목적 자체를 잘못 잡은 개념 문제는 조치가 다르다. 작은 문제를 크게 다루면 비용이 들고, 큰 문제를 작게 다루면 같은 결함이 돌아온다. 이 스킬은 문제를 단계로 나누고, 단계마다 근거 기준과 조치를 정한다.

## 단계

| 단계 | 대상 | 근거 기준 | 조치 | 승인 |
|---|---|---|---|---|
| L1 사소 | 문구, 표시, 설정 값, 설치본 차이 | 파일:줄 | 바로 고침(fix) | 없음 |
| L2 결함 | 버그, 실행 실패, 오판 1건 | 재현 사건 줄(.vibe/orch/events.jsonl), 실행 기록 | 원인을 고침(fix). systematic-debugging 의 근본 원인 단계를 따른다 | 없음 |
| L3 구조 | 같은 종류 결함이 되풀이됨 | 같은 원인으로 묶이는 사례 2건 이상의 대조표(사건 · 개선안 · 장부 줄) | 공통 원인(설계)을 없애는 구조 개선 | fix 면 없음, core 면 사용자 |
| L4 개념 | 구조를 고쳐도 목적이 계속 어긋남 | 목적 문서 인용 + 그 목적의 판정 이력 + L3 이력 | 개념 재정립안(vmo-concept-review 스킬) | 항상 사용자(core) |

## 단계 판정

1. 사건 · 점검 항목 · 사용자 지적 하나를 받으면 먼저 L1 또는 L2 로 본다.
2. 아래 중 하나가 참이면 L3 로 올린다.
   - 같은 서명 또는 같은 파일 영역 결함이 고친 뒤 다시 났다(재발 2건 이상)
   - 같은 파일을 7일 안에 4번 넘게 고쳤다
   - 같은 규칙의 오판이 2건 이상, 또는 같은 원인의 반영 실패가 2건 이상
   - 같은 사용자 지적 감지기가 해결 뒤 다시 걸렸다
3. 아래 중 하나가 참이면 L4 로 올린다.
   - L3 구조 개선을 반영했는데 며칠 안에 같은 묶음이 다시 참이 됐다
   - Overall Review 에서 같은 목적이 3번 연속 '어긋남'
   - 같은 목적을 두고 사용자 지적이 7일에 3건 이상
4. 판정을 결과에 적는다: `level: L1|L2|L3|L4`, `levelWhy: 올린 조건과 수치`.

## L3 구조 진단 방법

1. 묶음의 사례를 표로 놓는다. 사례마다 무엇이 났는지, 무엇을 고쳤는지, 왜 다시 났는지를 적는다.
2. 사례들이 공유하는 것을 찾는다. 같은 함수, 같은 가정, 같은 데이터 원천, 같은 시점(창 다시 로드, 동시 실행), 같은 판단 근거가 후보다.
3. 공통 원인 후보마다 '이 원인이 맞다면 무엇이 보여야 하는가'를 적고 소스와 기록에서 확인한다. 확인 못 한 후보는 버리거나 미확인으로 남긴다.
4. 구조 개선안은 공통 원인을 없애는 것이다. 사례 하나를 막는 안은 L2 로 돌려보낸다.
5. 개선안 verify 에 '묶음의 사례 전부가 다시 나지 않음'을 확인하는 시험(실제 사건 줄을 넣는 재현 시험)을 넣는다.

## 반증 시도(모든 단계)

결론을 내기 전에 '내 진단이 틀렸다면 무엇이 보여야 하는가'를 1개 이상 적고 확인한다. 확인할 수 없으면 결론에 '미확인'을 붙인다.

## 오판 확인(개입한 뒤)

VMO 가 사용자 작업에 손댄 일(중지, 다시 실행, 잠금 삭제, 자동 해결, 자동 반영)은 개입 장부 `.vibe/orch/interventions.jsonl` 에 있다. 진단 대상이 VMO 개입과 이어지면 장부의 전제(premise)와 판정(check.verdict)을 먼저 읽는다. 오판이면 원인은 VMO 규칙이다(사용자 작업 결함으로 보지 않는다).

## 쓰는 스킬

- systematic-debugging: L2, L3 의 원인 찾기
- verification-before-completion: 고쳤다고 말하기 전에 검증 명령을 돌리고 출력을 인용
- vmo-concept-review: L4
- writing-plans: 승인된 L4 전환을 실행 계획으로

## 지킬 것

- 감·예측 금지. 수치와 원인은 이번에 읽은 파일, 기록, 실행 결과만 인용하고 출처를 적는다. 못 확인했으면 '미확인'.
- 문장은 한국어 업무 문서 문체(수식어, 번역투, 줄표 금지).
- 할 일을 빼서 빠르게 만드는 안은 올리지 않는다(정합성이 같은 대체 방법만).
